# 로깅 온보딩 가이드 (소비 서비스 적용) — 정본

> **대상**: `common-platform` 로깅 기능을 새 API/배치 서비스에 적용하는 개발자·AI. **무설정으로 나오는 로그**부터
> **ECS 전환·opt-in 관측 계층·Elasticsearch 적재**까지, 소비자 관점에서 순서대로 적용한다.
>
> **관계 문서**: 일반 온보딩(전 기능) [260702.009](260702.009.ONBOARDING.md) · 로깅 **전략·설계·구현 현황** [260707.004](260707.004.ELASTIC_LOGGING_STRATEGY.md) ·
> ES 적재 아티팩트 [`deploy/elastic/`](../deploy/elastic/README.md) · 케이스별 로깅 순서 [260701.004](260701.004.LOGGING_CASES.md).
> 이 문서는 그중 **"소비 서비스가 로깅을 켜고 쓰는 법"** 만 모은 정본이다.

---

## 0. 30초 개요 — 무엇을 얻나

| 구분 | 기본 | 내용 |
|---|---|---|
| **무설정 자동** | ON | 요청 접근/완료(`access`), 예외(`error`), 인증·인가 위배(`security_audit`), 아웃바운드 호출(`http_client`), 도메인 이벤트(`domain_event`) 로그 |
| **포맷** | `dual` | 기존 필드 + **ECS(Elastic Common Schema)** 필드를 함께 출력(JSON Lines). Kibana/Elasticsearch 표준 |
| **opt-in 심화** | OFF | 입출력 본문(`payload`), 컨트롤러 진입(`controller`), 메서드 인자/리턴(`method`), 민감정보 마스킹 |
| **적재** | 별도 | 앱은 파일/stdout 으로 JSON 만 출력 → Filebeat/Agent 가 Elasticsearch data stream 으로 수집 |

로그는 **추적ID(`trace.id`)로 한 요청의 모든 계층이 묶인다**. 소비 서비스는 코드를 거의 안 짜고 설정만 한다.

## 1. 5분 온보딩

### 1.1 의존성 (스타터 1개 = 로깅 포함)
```xml
<dependency>
  <groupId>ai.mutuus.common</groupId>
  <artifactId>common-platform-starter-web</artifactId>   <!-- 배치는 -starter-batch -->
</dependency>
```
`starter-web`/`-batch` 가 **`logstash-logback-encoder`(JSON 인코더)를 이미 전이**한다. BOM import 는 [260702.009 §1.1](260702.009.ONBOARDING.md) 참조.

> **lib 만 직접 의존한다면** `logstash-logback-encoder` 를 직접 추가해야 한다(버전은 BOM). 미추가 시 기동 실패(`ClassNotFoundException: net.logstash...`).

### 1.2 로깅 활성화 (`src/main/resources/logback-spring.xml`)
```xml
<configuration>
  <property name="LOG_DIR" value="logs"/>       <!-- 운영 로그 경로(데모는 target/logs) -->
  <include resource="logback-common.xml"/>       <!-- 라이브러리의 JSON 콘솔 + 롤링파일(Async) appender -->
</configuration>
```
이 include 하나로 **JSON 콘솔 + 롤링 파일**(`<app-code>-<instance-code>.log`, 100MB+일자 롤링, 롤아웃분 `.gz`)이 켜진다.
콘솔·파일 모두 ECS 커스텀 필드(`ecs.version`/`service.*`/`data_stream.*`)와 MDC(추적/사용자)가 자동 포함된다.

### 1.3 최소 설정 (`application.yml`)
```yaml
spring:
  application: { name: my-service }
mutuus:
  common:
    service-name: my-service        # 로그 service.name (미지정 시 spring.application.name)
    app-code: MYSV                  # 4자리 영숫자(미지정 시 service-name 에서 결정적 도출)
    logging:
      environment: prod             # service.environment / data_stream.namespace 근거(미지정 시 활성 프로파일→local)
```
→ 기동하면 콘솔에 JSON 로그가 뜨고, 요청 1건마다 `request.completed` 가 남으면 성공.

## 2. 무설정으로 나오는 로그 (out-of-the-box)

| 로거 이름 | dataset(ECS) | 이벤트 | 발생 지점 |
|---|---|---|---|
| `ai.mutuus.common.access` | `mutuus.access` | `request.received` / `request.completed` | 요청 수신/완료(5xx·느린 요청 WARN) |
| `ai.mutuus.common.access` | `mutuus.error` | `error.business`(4xx) / `error.server`(5xx) | `GlobalExceptionHandler` |
| `ai.mutuus.common.security.audit` | `mutuus.security_audit` | `security.authn.failed`(401) / `security.authz.denied`(403) 등 | 보안 필터·MVC |
| `ai.mutuus.common.http.client` | `mutuus.http_client` | `http.client.completed` | 아웃바운드 RestClient/RestTemplate 호출 |
| `ai.mutuus.common.event` | `mutuus.domain_event` | `domain_event.published` / `domain_event.consumed` | `EventPublisher` 발행/소비 |

- **로거 이름이 나뉘어** 있어 소비자가 레벨을 개별 제어할 수 있다(예: `logging.level.ai.mutuus.common.http.client=WARN`).
- 요청/응답 필터(`access`)는 웹 환경에서만 등록된다. 아웃바운드(`http_client`)는 RestClient/RestTemplate 이 있을 때만.
- 자세한 케이스별 순서(필터/인터셉터/AOP): [260701.004](260701.004.LOGGING_CASES.md).

## 3. ECS 포맷과 필드

### 3.1 포맷 전환 (`format`)
```yaml
mutuus.common.logging.format: dual    # dual(기본) | ecs | legacy
```
- **`dual`**(기본): 기존 필드(`event`/`httpPath`/`durationMs`…) + ECS 필드(`event.action`/`url.path`/`event.duration`…)를 **함께** 출력 → 기존 대시보드 호환 유지하며 ECS 로 이관.
- **`ecs`**: ECS 필드만. **`legacy`**: 기존 필드만.

### 3.2 대표 ECS 필드 (access completed)
`event.action`·`event.dataset`·`event.category`·`event.outcome`·`event.duration`(nanos)·`http.request.method`·`url.path`·`http.response.status_code`·`client.ip` + MDC(`trace.id`/`span.id`/`transaction.id`/`user.id`) + 상수(`service.name`/`service.environment`/`service.node.name`/`ecs.version`/`data_stream.*`).
전체 필드·매핑은 [260707.004](260707.004.ELASTIC_LOGGING_STRATEGY.md) "공통 필드 표준".

### 3.3 인스턴스/환경 식별
| 값 | 프로퍼티 | 로그 필드 / 파일 |
|---|---|---|
| 서비스명 | `mutuus.common.service-name` | `service.name` |
| 앱코드(4) | `mutuus.common.app-code` | 파일명 앞부분, `service.node.name` 앞부분 |
| 인스턴스코드(6) | `mutuus.common.instance-code` | 파일명 뒷부분, `service.node.name` 뒷부분(미지정 시 기동 시 자동 생성) |
| 환경 | `mutuus.common.logging.environment` | `service.environment`, `data_stream.namespace` |

파일명 = `<app-code>-<instance-code>.log`. 이 값들은 로깅 초기화 **이전**에 확정되어 logback 이 시스템 프로퍼티로 읽는다.

## 4. opt-in 관측 계층 (기본 OFF)

컨트롤러 "안쪽"을 더 깊이 보려면 켠다. 민감/비용이 커서 기본 OFF다.

| 계층 | 토글 | 로거 | dataset | 필요 의존성 |
|---|---|---|---|---|
| 입출력 본문 | `mutuus.common.payload-logging.enabled=true` | `...payload` | `mutuus.payload` | 없음 |
| 컨트롤러 진입 | `mutuus.common.controller-entry.enabled=true` (+ `packages`) | `...controller` | `mutuus.controller` | 없음 |
| 메서드 인자/리턴 | `mutuus.common.method-logging.enabled=true` (+ `packages`) | `...method` | `mutuus.method` | aspectj(starter-web 제공) |
| 민감정보 마스킹 | `mutuus.common.logging.masking.enabled=true` | (payload/method 에 적용) | — | 없음 |

> **마스킹은 로그 한정** — 실제 응답 본문은 원문 그대로다. 카드/주민번호 등 PII 를 로그에 남기기 전에만 가린다.
> payload/method 를 켤 때는 **마스킹도 함께 켜는 것**을 권장(운영 기본 원칙: 짧은 retention + 마스킹).

깊이 차이: 필터(바이트 본문) / 인터셉터(메서드 식별, 인자 결정 전) / AOP(역직렬화된 값). 상세 [260701.004](260701.004.LOGGING_CASES.md).

## 5. 아웃바운드 HTTP · 도메인 이벤트 (기본 ON — 끄는 법)

둘 다 기본 ON이라 무설정으로 남는다. 소음이 크면 끈다.

```yaml
mutuus.common.http.client-logging:
  enabled: true                     # 아웃바운드 호출 로깅(false 로 OFF)
  slow-request-threshold-millis: 0  # >0 이면 초과 호출 WARN
mutuus.common.event:
  logging-enabled: true             # 도메인 이벤트 발행/소비 로깅(false 로 OFF)
```
- 아웃바운드 로그는 **URL 쿼리스트링을 제외**하고 남긴다(토큰/비밀 유출 방지). 주입받은 `RestClient.Builder`/`RestTemplateBuilder` 로 만든 클라이언트에 자동 적용.
- 도메인 이벤트 소비 로그는 **in-process 전달** 기준(외부 브로커로 대체 시 그 구현이 담당).

## 6. 로깅 튜닝 프로퍼티 카탈로그

```yaml
mutuus.common.logging:
  enabled: true                     # 액세스 로깅 전체 토글
  format: dual                      # dual | ecs | legacy
  environment: prod                 # service.environment / data_stream.namespace
  data-stream: { namespace: prod }  # 미지정 시 environment 사용
  include-query-string: true        # 수신 로그에 쿼리스트링 포함
  exclude-path-prefixes: [/actuator]# 로깅 생략 경로(헬스체크 노이즈 감소)
  slow-request-threshold-millis: 0  # >0 이면 초과 요청 completed 를 WARN
  masking: { enabled: false }       # 민감정보 마스킹
```
레벨은 표준 스프링 방식: `logging.level.ai.mutuus.common.<access|security.audit|http.client|event|payload|controller|method>=…`.

## 7. Elasticsearch 적재 연결 (선택)

앱은 **Elasticsearch 에 직접 쓰지 않는다**. 파일/stdout 의 JSON 을 수집기가 data stream 으로 넣는다.

1. 앱: `logback-common.xml` 로 ECS JSON Lines 출력(위 §1.2).
2. 플랫폼: [`deploy/elastic/`](../deploy/elastic/README.md) 의 ingest pipeline·템플릿·ILM 등록 + Filebeat 설정.
3. Kibana: `logs-mutuus.*` data view 생성 → Discover/Lens.

Discover 필드 노출·집계 축 조건(차원=keyword/값=long·ip·date, `trace.id` 드릴다운)은 [260707.004](260707.004.ELASTIC_LOGGING_STRATEGY.md) "Kibana Discover 활용" 참조.

## 10. 자주 겪는 함정

- **기동 시 `ClassNotFoundException: net.logstash...`** → `logback-common.xml` 은 logstash 인코더 필요. 스타터가 제공하나, lib 직접 의존 시 `logstash-logback-encoder` 추가(버전 BOM).
- **로그에 필드가 두 벌(예 `event` + `event.action`)** → `format=dual`(기본)이라 정상. ECS 만 원하면 `format=ecs`.
- **Kibana 에서 `service.name` 은 있는데 bare `service` 가 없다** → 의도된 것. ECS `service.*` 와 bare `service` 는 매핑 충돌이라 `service` 는 ECS 중첩으로만 출력한다.
- **아웃바운드 로그가 너무 많다** → `mutuus.common.http.client-logging.enabled=false` 또는 로거 레벨 상향.
- **`trace.id`/`transaction.id` 로 집계(Terms)했더니 폭발** → 고카디널리티. 이 둘은 **필터·Cardinality(unique count) 전용**, 집계 축으로 쓰지 말 것.
- **비웹 배치에 웹 로그가 안 남음** → 정상. 요청/응답·아웃바운드 로깅은 웹 전용(조건부 자동구성). 배치는 `event`/예외/추적만.
- **payload/method 로그에 PII 노출** → `mutuus.common.logging.masking.enabled=true` 로 마스킹(로그 한정).
