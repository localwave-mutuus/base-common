# 0.4.1 — 조용한 서비스의 닫힌 로그 공개

로그가 한 번 기록된 뒤 요청이 없어도 수집 가능한 닫힌 파일을 주기적으로 만든다. 기존 시간 경계·크기·정상 종료 회전은 유지하며, 별도 로그 이벤트나 heartbeat를 생성하지 않는다.

- 조절값은 `GS_LOG_FORCE_ROLL_SECONDS` 하나다. 기본300초, 0은 타이머 비활성화, 음수·정수가 아닌 값은 설정 오류다. YAML에서는 같은 값의 `mutuus.common.logging.file.force-roll-seconds`를 사용하며 env가 우선한다.
- common Logback include가 파일 appender의 타이머를 시작한다. 쓰기가 있는 활성 파일만 회전하며 빈 압축 파일은 만들지 않는다. 종료 시 타이머를 취소하고 마지막 파일을 닫는다.
- 파일명 `<env>-<app>-<serial>-<pid>.<yyyyMMdd-HH>.<n>.log.gz`와 UTC 시간 버킷을 유지한다. 같은 시간 안에서는 순번만 증가하고 기존 원자적 gzip+rename을 거쳐 완료된 이름을 공개한다.
- 파일 쓰기·주기 회전·종료는 직렬화한다. 기존 비동기 큐의 정상 종료 flush와 마지막 회전을 유지하고, 공용 스케줄러 자체를 종료하지 않는다.
- 서비스별 emitter·필드·마스킹·OTel 설정은 바꾸지 않는다. 레지스트리v3/schema2와 출력 필드 목록도 동일하다.

소비자는 common-platform BOM/스타터를0.4.1로 올리고 기존 파이프라인으로 배포한다. 기본값이면 추가 env 설정이 필요 없다. 기존 sidecar/배치 전송5분과 ingest-v2 5분을 유지해 로그 발생부터 조회까지 목표 지연은15분이다. 실제 조용한 서비스 요청1건의 trace가15분 안에 조회되는지는 배포 후 검증한다.

되돌림은 `GS_LOG_FORCE_ROLL_SECONDS=0` 또는 이전 아티팩트 사용이다. 0은 타이머만 끄며 기존 시간·크기·종료 회전은 유지한다.0.4.0 게시 아티팩트나 태그는 변경하지 않는다.

검증: 소비 샘플의 실제 타이머 quiet-write 회전, 같은 시간 순번 증가, 빈 압축 파일 방지,0비활성화, 동시 쓰기·회전·종료 및 env 우선순위 회귀. 게시 전 집중 시험과 기존 stable 태그 workflow 전체 검증을 수행한다.
