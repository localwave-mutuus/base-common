# common-platform 0.4.0 — schema v2

좌표는 `ai.mutuus.common:{common-platform-parent,common-platform-bom,common-platform,common-platform-starter-web,common-platform-starter-batch}:0.4.0`이다. Java21·Spring Boot4.1.0·OTel API/BOM1.62.0을 사용한다. Java agent2.28.1의 SHA-256은 `faa89bdeebf9b1f52be4a4374689176717b02a59df2d8f8b6eb9aa39f9292589`, semconv 기준은1.41.1이다. 기존 게시 버전과 태그는 보존한다.

## 입력과 출력

공통 모듈은 정본 필드 이름만 받으며 schema v2 중첩 JSON 한 줄을 출력한다. 옛 MDC/KV 입력 변환·별칭·출력 형식 선택은 제거했다. 서비스는 입력 키를 정본으로 직접 바꾼다. 등록되지 않은 MDC 값과 키 이름은 저장하지 않고 `golmok.attributes.unmapped_count`로 건수만 남긴다. raw 사용자 헤더·baggage는 인증 근거가 아니다.

필드 정본은 [log-fields.v2.json](../lib/src/main/resources/common-platform/log-fields.v2.json) 한 파일이다. 레지스트리 version3은 필드 정의 판본이며 로그 schema는2다.89개 정본 필드(필수15/상황53/선택21)의 이름·형식·등급·뜻·범위·민감도·소유자를 관리한다. `golmok.merchant.id`는 서버가 조회한 단일 업체 ID다. 설정 키·enum·헤더는 코드에서 관리한다. 빌드가 encoder 허용 목록과 `common-platform/generated/{fields.md,fill-rate-rules.json,opensearch-template.preview.json}`을 생성한다. 실제 인덱스 템플릿·수집기·채움률 대시보드는 인프라 owner가 레지스트리에서 생성한다.

## 실행 설정

Java agent가 SDK/provider를 소유한다. 공통은 GlobalOpenTelemetry API를 사용한다. `management.tracing.enabled=false`, `OTEL_PROPAGATORS=tracecontext`, `OTEL_TRACES_SAMPLER=always_on`, `OTEL_TRACES_EXPORTER=otlp`, `OTEL_METRICS_EXPORTER=none`, `OTEL_LOGS_EXPORTER=none`을 설정한다. 현재 로그 정본은 파일→S3 경로다. P0 v1.8에 따라 `OTEL_INSTRUMENTATION_LOGBACK_APPENDER_ENABLED=false`, `OTEL_INSTRUMENTATION_LOGBACK_MDC_ENABLED=false`로 자동 appender와 MDC 사본을 끈다. 공통 SnapshotAppender는 생성 순간의 문맥과 event.id를 고정한다. trace/span은 현재 Span API에서 읽는다.

`OTEL_SERVICE_NAME`과 `OTEL_RESOURCE_ATTRIBUTES`의 service.version·service.instance.id·deployment.environment.name은 배포 owner가 공급한다. instance.id는 기동 직전 정한 한 값을 agent Resource와 JSON 양쪽에 쓴다. 누락 시 JSON에서 생략하고 경고한다. OTLP endpoint·TLS·인증 값은 owner 보호 설정에서만 공급한다.

서비스 logback 설정은 `<configuration><include resource="common-platform/logback/common.xml"/></configuration>`과 필요한 property를 사용한다. 유일한 SnapshotAppender와 비동기 파일 경로를 유지한다. 독립 예약 실행을 직접 감싸면 해당 agent scheduling 계측을 끈다. agent가 전파하는 실행기에 공통 decorator를 중복 부착하지 않는다. 공통 decorator 기본값은 false다.

## 신원과 작업 문맥

검증 JWT subject/member가 기본 인증 adapter다. 다른 principal은 `AuthenticationIdentityAdapter`로 내부 ID/realm을 명시한다. 자체 SecurityFilterChain에는 bearer 인증 뒤·인가 앞에 부착한다. 인증된403의 신원을 유지한다. 처리된 BusinessException·검증/보안 예외는 실제 클래스 이름만 메타데이터로 기록해 오류 로그와 요청 완료 로그의 `error.type`을 채운다. 응답의 예외 노출 정책은 유지한다.

`TelemetryEnvelope.captureCurrentVerified(operationId,attemptId)`는 W3C 부모·검증 initiator·메시지 UUID·발행 시각을 담는다. 저장 owner는 업무와 같은 트랜잭션에 보관하고 소비 권한을 재평가한다. `openConsumerFromOwnerValidatedStorage`는 새 consumer span/execution을 만들며 재시도는 `withAttemptId`로 구분한다. raw JWT/baggage는 저장하지 않는다.

독립 실행은 `JobPairLogger.begin`, 원인 link가 있는 새 root는 `beginRootLinked`, 이미 열린 consumer span 안 로그 범위는 `beginInCurrentSpan`을 사용한다. 후자는 유효 span과 TelemetryMetadata execution ID가 필요하며 같은 execution/operation을 쓰고 빌린 span을 종료하지 않는다. 일반 작업 로그도 동일 문맥을 받는다.

## 검증과 승격

정식 태그의 기존 전체 검증·게시·독립 소비 관문을 따른다. 실제 agent·Resource 일치·수집·trace/user 조회는 DEV에서 검증하고 PROD MR을 진행한다. PROD 증명은 승인된 읽기 요청만 수행한다. 테스트 결과와 실제 환경 관찰은 구분해 보고한다.
