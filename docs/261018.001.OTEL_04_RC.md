# common-platform 0.4.0-rc.1 DEV 전환

이 시험판은 Java agent가 SDK/provider를 소유하고 공통 모듈은 OpenTelemetry API만 사용하는 전환본이다. 기존 0.3.0 패키지를 바꾸지 않는다. 게시 모듈은 `ai.mutuus.common:{common-platform-parent,common-platform-bom,common-platform,common-platform-starter-web,common-platform-starter-batch}:0.4.0-rc.1`이다. API/BOM은 1.62.0, agent는 P0 계약의 2.28.1(SHA-256 `faa89bdeebf9b1f52be4a4374689176717b02a59df2d8f8b6eb9aa39f9292589`), semconv 상수 기준은 1.41.1, 대상 JVM은 Java21, Spring Boot4.1.0이다. agent 바이트·실제 환경 호환 판정은 프로그램 P0 계약과 DEV 파일럿을 따른다.

## 필수 설정과 소유권

- 승인한 Java agent를 JVM 시작 때 한 개만 부착한다. 별도 OTel Spring starter, Micrometer tracing bridge, SDK provider 자동 구성을 함께 켜지 않는다. `management.tracing.enabled=false`; SDK/API 자동 구성을 서비스 설정으로 다시 켜지 않는다.
- `OTEL_PROPAGATORS=tracecontext`, `OTEL_TRACES_SAMPLER=always_on`, `OTEL_TRACES_EXPORTER=otlp`, `OTEL_METRICS_EXPORTER=none`. P0 v1 단계에서 **`OTEL_LOGS_EXPORTER=none`**(파일→S3 정본 유지), OTLP 로그 활성은 동일 event.id 중복방지 검증 뒤 owner 계약 개정으로만 수행한다. API emitter는 준비돼 있지만 실제 로그 OTLP 전송 완료를 주장하지 않는다. exporter protocol·endpoint·인증 값은 환경 owner 계약으로 공급한다. 코드나 이 문서에 값을 복제하지 않는다.
- `OTEL_SERVICE_NAME`과 `OTEL_RESOURCE_ATTRIBUTES`의 서비스 버전·인스턴스·환경은 owner가 공급한다. `deployment.environment.name=development`를 사용한다. `service.instance.id`는 기동 직전 owner가 정한 한 값을 agent와 JSON에 같이 공급하며 agent나 공통 모듈이 별도로 생성하지 않는다. 누락 시 JSON에서 생략하고 기동 경고를 남긴다. 실제 JVM의 자동계측과 수집 경로는 DEV 파일럿에서 검증한다.
- **`OTEL_INSTRUMENTATION_LOGBACK_APPENDER_ENABLED=false`**. 공통 SnapshotAppender가 동일한 event.id와 문맥을 Global LogsBridge에 보내고 파일에 보관한다. agent의 자동 Logback appender까지 켜면 중복 전송된다. 로그 SDK/exporter는 여전히 agent 소유이며 공통 모듈이 provider를 만들지 않는다.
- 독립 예약 실행을 `JobPairLogger`로 감싸는 서비스는 `OTEL_INSTRUMENTATION_SPRING_SCHEDULING_ENABLED=false`로 그 경계의 중복 span을 막는다. 서비스 owner는 실제 예약 실행 manifest와 대조한다. agent가 전파하는 실행기는 공통 decorator를 중복 부착하지 않는다. `mutuus.common.async.context-decorator-enabled` 기본값은 false다. 직접 관리하는 비계측 실행기는 명시적 Context wrapper/업무 span API를 사용한다.
- 서비스 `logback-spring.xml`은 `<configuration><include resource="common-platform/logback/common.xml"/></configuration>`와 서비스별 property만 둔다. include가 root의 유일한 SnapshotAppender, 콘솔, 비동기 파일을 제공한다. 다른 root appender나 encoder를 중복 선언하지 않는다. 구 `logback-common.xml`은 같은 include를 가리키는 호환 경로다. DUAL 이름은 API 호환만 유지하며 새 JSON은 canonical 단일 필드만 출력한다.
- 인증 adapter 기본은 검증된 JWT subject/member realm이다. 별도 principal은 `AuthenticationIdentityAdapter`로 불변 내부 ID와 realm을 명시한다. 자체 SecurityFilterChain은 bearer 인증 뒤, ExceptionTranslationFilter/인가 앞에 필터를 붙인다. 헤더·baggage·getName만으로 user.id를 만들지 않는다. 401은 failed, 인증된403은 사용자 문맥을 유지한다.

## 전체 공통 항목

프로그램의 `100.TODO/.team/state/tasks/261018-otel-impl/common-fields.md`가 baseline 소스/문서의 필드·헤더·MDC·속성·이벤트 전체 362개와 채우는 owner/시점을 기록한다. 같은 뜻의 별칭은 한 이름으로 수렴한다. 화면/업무/감사/payload의 고유 의미는 삭제하지 않는다. 사용자·IP·본문 등의 보호 규칙과 payload opt-in은 유지한다. 값이 없는 항목을 가짜 값으로 채우지 않으며 서비스별 채움률은 DEV 파일럿 이후 산정한다. core facade가 API를 직접 사용하므로 순수 lib 소비자에게도 작은 OTel API만 전이한다. SDK·exporter·web/security 통합은 전이시키지 않는다.

P0 v1.1 형식: `golmok.schema.version=2`를 모든 로그에 기록한다. 미등록 MDC는 원문 값을 내보내지 않고 `attributes.<키>=REDACTED_UNREVIEWED`로 남긴다. 키는 `[A-Za-z0-9_.-]{1,64}`, 이외는 `attributes.invalid_key`로 합치고 최대16개만 유지한다. `golmok.attributes.unmapped_count`는 전체 미등록 키 수다. 검토 후 명시적 매핑으로 승격하며 임의 MDC 전체 값 방출은 하지 않는다.

## 검증 범위와 복구

RC 태그 워크플로는 승인된 공통 영향 계약 시험과 별도 Maven 저장소에서 게시 패키지를 받는 소비 시험을 수행한다. 안정판 태그의 전체 검증은 유지한다. 이 RC의 로컬 SDK 계약 시험은 실제 서비스에 agent를 부착한 DEV E2E를 대체하지 않는다. Java21/Spring4.1 조합의 agent 자동계측·실제 원격 전파/저장·ARM64는 파일럿/P0 소유자 증거로 별도 판정한다. 실패 시 서비스의 기존 BOM0.3.0·설정·실행 이미지를 함께 복원하며 RC 패키지/tag는 덮어쓰지 않는다.

근거: [Java agent/API 결합](https://opentelemetry.io/docs/zero-code/java/agent/), [agent 설정](https://opentelemetry.io/docs/zero-code/java/agent/configuration/), [계측별 비활성화](https://opentelemetry.io/docs/zero-code/java/agent/disable/).

## 영속 메시지 봉투 API

`TelemetryEnvelope.captureCurrentVerified(operationId, attemptId)`는 유효한 현재 span과 검증 사용자만 캡처한다. version1, W3C 부모, 최초 검증 사용자 ID/realm/source, 메시지 event UUID, 발행 시각, 선택 operation ID와 attempt ID를 불변 보관한다. raw JWT·baggage는 포함하지 않는다. Global propagator는 tracecontext를 제공해야 하며 잘못된 버전·형식·길이·부모 또는 현재 span 부재는 거부한다. 별도 추적 ID를 생성해 결함을 숨기지 않는다.

Stage B 저장 adapter owner는 발행 권한을 검증하고 이 봉투와 업무 데이터를 같은 트랜잭션으로 보관해야 한다. `extractFromOwnerValidatedStorage()`는 owner가 검증한 저장소에서만 호출한다. 임의 HTTP 입력으로 사용하면 인증이 되지 않는다. 원래 사용자 권한으로 작업을 실행한다는 뜻이 아니며 소비 권한은 별도로 재평가한다. 기존 DomainEvent API는 유지한다.

직접 계측하는 소비 경계는 `try (var consumer = envelope.openConsumerFromOwnerValidatedStorage("queue.consume")) { ... }`를 사용한다. 실패 시 `consumer.fail()`을 호출한다. 재시도는 `withAttemptId(nextAttemptId)`로 원래 부모·메시지 ID·최초 사용자를 유지하고 새 CONSUMER span과 execution UUID를 생성한다. 이미 agent가 CONSUMER span을 만드는 경계에는 중복 적용하지 않는다. 종료하면 이전 Context/사용자/메타데이터를 복원한다.

일반 소비 로그도 `golmok.scope=job`, `golmok.identity.source=verified_initiator`, `operation.id`, `golmok.attempt.id`, `golmok.message.event.id`, `execution.id`를 현재 Context에서 받는다. `golmok.message.event.id`는 영속 메시지 식별자이며 로그 발생 건마다 생성되는 `event.id`를 덮어쓰지 않는다. DB schema/저장 트랜잭션/실제 재시작 복원은 Stage B owner 작업이며 이 공통 API 시험으로 완료를 주장하지 않는다.
