# PostgreSQL-only Migration Context

## 결정

`common-platform`의 DB 기준은 PostgreSQL이다. 앞으로 공통모듈 검증, 샘플 검증, jOOQ 코드 생성, DB-backed configuration 검증은 H2를 새 기준으로 삼지 않는다.

현재 외부 PostgreSQL 대상 DB 이름은 `golmok`으로 안내한다. 과거에 공유된 다른 DB명은 사용하지 않는다.

## 현재 상태

아직 `sample-api`에는 과거 무인프라 검증을 위해 H2가 남아 있다.

- `samples/sample-api/src/main/resources/application-ai.yml`: `ai` 프로파일의 임베디드 H2 DataSource
- `samples/sample-api/pom.xml`: H2 의존성
- `samples/sample-api/src/main/java/.../DbDemoSupport.java`: 데모용 H2/Atomikos XA 리소스
- 일부 샘플 테스트: H2 기반 통합 검증
- 일부 문서: 과거 H2/PostgreSQL 공통 DDL 설명

이 상태는 영구 정책이 아니라 전환 중 상태다. 새 기능과 새 테스트는 PostgreSQL 기준으로 작성하고, 기존 H2 경로는 PostgreSQL Testcontainers 또는 명시 opt-in live PostgreSQL 검증으로 대체한 뒤 제거한다.

## Modulith/DB 경계

DB 엔진 전환 자체는 Spring Modulith의 바운디드 컨텍스트가 아니다. Modulith 컨텍스트는 업무 소유권을 나누고, PostgreSQL은 그 컨텍스트들을 담는 인프라다.

권장 소유 경계는 다음과 같다.

```text
ai.mutuus.sample
  board          -> board schema/table
  demo           -> demo scenario data
  logs           -> log viewer
  persistence    -> auditing sample data
  web            -> web entry sample
  configuration  -> DB-backed property
```

PostgreSQL `golmok` 안에서는 schema로 소유권을 드러낸다.

```sql
create schema if not exists board;
create schema if not exists demo;
create schema if not exists configuration;
```

예상 테이블:

```text
board.board_post
board.board_like
board.board_comment
demo.sample_note
configuration.common_config_property
```

## 전환 원칙

1. 공통모듈과 샘플의 새 테스트에서 H2를 추가하지 않는다.
2. 자동 단위/슬라이스 테스트는 DB 연결 없이 mock, `ApplicationContextRunner`, 또는 PostgreSQL URL 기반 설정 검증으로 작성한다.
3. 통합 DB 검증은 PostgreSQL Testcontainers를 우선한다. Docker가 없으면 skip이어야 한다.
4. live PostgreSQL 검증은 명시 opt-in 시스템 프로퍼티와 접속 정보가 있을 때만 수행한다.
5. 고정 포트 서버를 테스트 중 자동 기동하지 않는다. 필요 시 `RANDOM_PORT` 또는 샘플 포트 정책 문서의 수동 슬롯만 사용한다.
6. H2 의존성 제거는 H2 import, URL, 테스트, 데모 리소스가 0개가 된 뒤 진행한다.

## jOOQ Codegen 정책

권고안은 “jOOQ 코드젠 내부 H2 시뮬레이션도 금지”다. 따라서 기본 Maven 빌드에서는 jOOQ `DDLDatabase`를 실행하지 않는다. 기본 빌드와 테스트는 체크인된 생성 소스를 컴파일만 하며 DB 연결을 열지 않는다.

생성 소스를 다시 만들 때만 `pg-codegen` 프로파일을 명시적으로 켜고 PostgreSQL metadata에서 생성한다.

```powershell
$env:JOOQ_CODEGEN_URL = "jdbc:postgresql://<host>:12556/golmok?sslmode=require"
$env:JOOQ_CODEGEN_USERNAME = "<user>"
$env:JOOQ_CODEGEN_PASSWORD = "<rotated-password>"
.\mvnw.cmd -pl samples/sample-api -Ppg-codegen -Dpg-codegen generate-sources
```

schema가 분리되어 있으면 명시한다.

```powershell
.\mvnw.cmd -pl samples/sample-api -Ppg-codegen -Dpg-codegen -Djooq.codegen.schema=board generate-sources
```

비밀번호는 명령 히스토리에 직접 남기지 않는 방식이 더 안전하다. 로컬에서는 레포 밖 외부 파일이나 일회성 셸 세션을 사용하고, CI/CD에서는 해당 플랫폼의 secret store로 주입한다.

## 공통모듈 개선 기준

공통모듈은 특정 DB 엔진을 강제하지 않되 PostgreSQL 운영 전환에서 설정 오류가 늦게 발견되지 않도록 fail-fast 검증을 강화한다.

- datasource group의 `write.url` 필수 검증
- `primary`가 실제 group을 가리키는지 검증
- pool size, read/write URL, driver class 설정의 명확한 오류 메시지
- Hikari가 classpath에 없을 때 자동구성이 활성화되지 않는 조건
- 테스트는 H2 연결 대신 PostgreSQL URL과 routing key 단위 검증
