# 암호화 시크릿 로더 구현 및 sample 검증

## 1. 결론

Offline Secret Manager v2 계획을 `common-platform` 단일 JAR에 반영했다. 소비 서비스는 복호화 코드를 복제하지 않고 `mutuus.common.secret.enabled=true`와 파일 locator, `secret:v2:inline:` 값만 설정한다.

현재 구현 범위는 `spring.datasource.password` 하나다. Redis/JWT/OAuth 비밀값, Vault/KMS 연동, 키 발급·배포·rotation은 이번 범위가 아니다.

## 2. 구현 구조

```text
lib/src/main/java/ai/mutuus/common/secret/
├─ EncryptedSecretEnvironmentPostProcessor.java
├─ EncryptedSecretResolver.java
├─ DefaultEncryptedSecretResolver.java
├─ EncryptedSecretRecord.java
├─ SecretBootstrapProperties.java
└─ SecretResolutionException.java
```

`EncryptedSecretEnvironmentPostProcessor`는 `META-INF/spring.factories`에서 기존 `CommonEnvironmentPostProcessor`와 함께 등록된다. Config Data 이후에 다음 순서로 동작한다.

1. opt-in과 필수 부트스트랩 설정을 확인한다.
2. `spring.datasource.password`의 실제 PropertySource를 개별 검사한다.
3. 평문과 암호문이 동시에 있거나 두 source가 값을 제공하면 시작을 중단한다.
4. v2 레코드와 메타데이터, PKCS#12 alias, RSA/AES-GCM 인증을 검증한다.
5. 모든 대상이 성공한 경우에만 `mutuusDecryptedSecrets`를 최우선으로 등록한다.
6. 임시 `char[]`/`byte[]`는 지우고 target·keyId·formatVersion·결과만 로그로 남긴다.

## 3. sample 적용

`samples/sample-api/src/main/resources/application-secret-local.yml`은 실제 값을 포함하지 않는 소비 예제다.

```yaml
spring:
  datasource:
    url: ${GOLMOK_DB_URL}
    username: ${GOLMOK_DB_USER}
    password: ${GOLMOK_DB_PASSWORD_TOKEN}

mutuus:
  common:
    secret:
      enabled: true
      environment: local
      keystore: ${SAMPLE_SECRET_KEYSTORE}
      keystore-password-file: ${SAMPLE_SECRET_KEYSTORE_PASSWORD_FILE}
```

프로파일은 DB 변경을 막기 위해 Flyway와 Hibernate DDL을 끄고 Hikari를 read-only로 연다. 암호문은 `program=sample-api`, `environment=local`, `configKey=database.password`로 생성해야 한다. Golmok용 `program=golmok-backend` 암호문을 그대로 재사용하면 메타데이터 불일치로 거부되는 것이 정상이다.

## 4. 검증 구성

| 검증 | 내용 |
|---|---|
| resolver 단위 | 정상 복호화, program/environment/configKey, keyId, v1, unknown/duplicate, oversize, wrong password, AAD/ciphertext 변조, 빈 평문 |
| bootstrap | 실제 SpringApplication에서 Config Data 이후 processor 등록·실행 |
| source 정책 | opt-out 무개입, 암호문+평문 충돌 fail-closed, 실패 시 부분 PropertySource 없음 |
| 감사 정책 | 활성화된 canonical inline 값은 평문 경고 제외, 비활성 값은 계속 경고 |
| web/batch 회귀 | 기본 OFF에서 기존 sample-api/sample-batch 시작 동작 유지 |
| Golmok live | 외부 Golmok YAML의 URL/사용자/비밀번호를 읽고 비밀번호만 임시 v2 암호문으로 바꿔 sample DataSource에서 `SELECT 1` |

테스트용 RSA 개인키와 PKCS#12는 JDK `keytool`로 JUnit 임시 디렉터리에 매번 생성한다. Git에는 테스트 개인키나 bootstrap 비밀번호 파일을 두지 않는다.

실행 명령:

```powershell
.\mvnw.cmd -pl samples/sample-api -am clean `
  '-Dtest=EncryptedSecretGolmokPostgresLiveIntegrationTest' `
  '-Dsurefire.failIfNoSpecifiedTests=false' `
  '-Dlive.golmok.secret.enabled=true' test
```

이 명령은 기본적으로 `${user.home}/.mutuus/golmok-backend/local.yml`을 읽되 값을 출력하지 않는다. 별도 파일을 쓸 때는 `-Dlive.golmok.config=<path>`만 지정한다. 비밀번호를 Maven/JVM 인자로 전달하지 않는다.
