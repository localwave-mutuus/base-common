# 0.2.5 요청·작업 짝 및 닫힌 로그 파일

공통 구현은 `lib/`에만 있다. 소비 서비스는 BOM 0.2.5와 `common-platform-starter-web` 또는 비웹 `common-platform-starter-batch`를 사용하고, `logback-spring.xml`에 `<configuration><include resource="logback-common.xml"/></configuration>`만 둔다. 스타터의 optional 경계와 기존 보안/업무 흐름은 유지한다.

## 설정

`mutuus.common.service-short-name=app|member|bo|batch`, `logging.environment=local|dev|prod`, `logging.serial`(소문자 영숫자8자리), `logging.directory`를 `mutuus.common` 아래 지정한다. 기존 service-name/app-code는 유지한다. serial은 `GS_LOG_SERIAL`로도 주입할 수 있다. ECS task id 앞8자리 또는 VM instance id 끝8자리는 소유 배포 코드가 제공하며 라이브러리는 metadata HTTP를 호출하지 않는다. LOCAL 미지정만 랜덤8자리, DEV/PROD 미지정은 기동 오류다. 구형 sample의 stage/ai처럼 logging.environment가 없는 다른 프로파일은 파일 환경만local로 처리한다. 디렉터리는 LOCAL의 지정 경로, 컨테이너 `/runtime/logs`, VM `/var/log/gs`; directory 미지정이면 기존 LOG_DIR 또는logs를 따른다.

## 짝

HTTP 필터는HIGHEST_PRECEDENCE, TraceFilter는+1이다. requestId와trace.id를 요청 속성/불변 상태에 보관하고, 동기finally 및AsyncListener의complete/timeout/error를AtomicBoolean으로 한 번만 마감한다. startAsync 반환 전에listener를 등록하고 재시작 cycle에 다시등록한다. 보안401/403, 4xx/500, 예외, timeout, disconnect도기록한다. `/actuator` 및`/actuator/**`만 두 줄 모두제외한다. 구형 추가exclude-prefix는 짝 필터에 적용하지 않는다.

`http.request.in`/`http.response.out`에requestId,trace.id,url.path,http.response.status_code,event.duration(ns),durationMs,status,outcome(OK/ERROR),errorCode/error.code를 항상남긴다. 수신 시status/duration은0, 정상error code는빈문자열이다. 종료시HTTP 오류는HTTP_상태코드, 미처리예외는UNHANDLED_EXCEPTION, timeout은ASYNC_TIMEOUT/504, 끊김은CLIENT_DISCONNECT/499다. 후자의상태는관측 종료사유이며wire응답을바꾸지 않는다. query는민감값 보호를 위해 소비설정 `include-query-string=false`를권장한다. 별도auth/error진단 이벤트는짝이아니며검사에서제외한다. 기존AccessLogger 직접메서드의구형API는호환용으로남기되공통필터는새이벤트만낸다.

비웹 `JobPairLogger.begin(jobName, operationId)`는lease획득후호출하고try-with-resources로닫는다. scope.success/fail(fixedCode)/fail(Throwable,fixedCode)/cancel을호출한다. 성공OK, 실패ERROR, CancellationException/InterruptedException/interrupt는CANCELLED. 미표시close는JOB_SCOPE_UNFINISHED(ERROR), interrupt는JOB_CANCELLED. 중복 종료는무시하며invocation마다새UUID의jobExecutionId/execution.id/requestId와새trace.id를갖는다. job.start/job.end에duration과고정error.code를남기고예외메시지/업무payload/비밀은받지않는다. 기존엔진state/영수증/재시도 의미는소비자소유다.

## 닫힌 파일

active `<env>-<app>-<serial>-<pid>.log`는수집금지다. UTC시간또는100MB에굴리고종료시마지막비어있지않은파일도닫는다. writer close→`.log.pending`→`.log.gz.part-UUID`로압축→gzip close→원자rename하여`<base>.<yyyyMMdd-HH>.<n>.log.gz`를공개한다. 수집기는이름정규식만사용한다:

```
^(local|dev|prod)-(app|member|bo|batch)-[0-9a-z]{8}-[0-9]+\.[0-9]{8}-[0-9]{2}\.[0-9]+\.log\.gz$
```

순번예약은`.<base>.sequence`에동기쓰기/원자교체,파일잠금으로영속화한다. 수집후archive가모두지워져도번호를재사용하지않는다. 장부/lock는삭제·수집금지이며동일serial/PID 재시작에서디스크가보존되어야한다. 원자rename을지원하지않는파일시스템은fail-safe한다. 자동maxHistory/size-cap삭제는없다(업로드확인후삭제는수집기소유). 실패는LOG_ARCHIVE_FAILED와pending/part원본을보존하며닫힌이름을노출하지않는다. 실패pending은소유자복구대상이며자동으로수집하면안된다.

AsyncAppender는discardingThreshold=0,neverBlock=false,maxFlushTime=0으로큐를모두비운뒤하위appender를닫는다. Spring Boot4.1 logging lifecycle phase는MIN_VALUE+1이며일반scheduler/engine lifecycle drain뒤파일종료한다. 응용의임의JVM hook,강제kill/OS crash의finally는보장범위밖이다. 정상종료시gzip공개완료뒤에만수집할수있다.

## 검증·게시

소비sample-api의HttpPairLoggingIntegrationTest는실제Tomcat/SpringSecurity/소켓RST로200/4xx/401/403/500/예외/async완료/timeout/disconnect 각1건을검증한다. HttpPairAsyncLifecycleTest는error/complete/timeout 중복및cycle재등록을검증한다. ClosedFileRollingPolicyTest는크기/시간/종료/재시작/수집삭제뒤순번을확인한다. sample-batch의JobPairLoggingTest는서블릿클래스부재와작업5종을검증한다. 자체확인이고독립리뷰는별도다.

`python tools/check-log-pairs.py <모든 진단파일 .jsonl 또는 .gz>`로파일경계에걸친짝을합산한다. nested/dotted JSON,HTTP/job 누락·중복·trace mismatch·invalid fields·invalid JSON·빈입력을검사한다. active읽기는LOCAL진단만이며S3에는닫힌이름만보낸다.

게시처는[GitHub Packages 게시 안내](260827.003.GITHUB_PACKAGES_PUBLISHING.md)의기존태그workflow다(Nexus가아님). 게시성공후parent/BOM/lib/두starter의POM/JAR SHA256을105에인계하고offline runner seed완료뒤서비스승격한다.
