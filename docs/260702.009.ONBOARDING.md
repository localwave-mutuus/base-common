# common-platform 온보딩 가이드 (소비 서비스 적용)

> **대상**: `common-platform`(공통 라이브러리)을 새 API/배치 서비스에 적용하는 개발자·AI. **5분 안에** 표준 스택
> (추적·로깅·예외·i18n·보안위임·멱등·이벤트)을 얻고, 필요한 기능만 프로퍼티로 켠다. 산출물은 **스타터 1개 + BOM**
> 으로 소비한다(라이브러리 내부를 직접 참조하지 않는다).
>
> 참조: 아키텍처 원칙은 프로젝트 [CLAUDE.md](../CLAUDE.md), DDD 설계는 [260702.007](260702.007.PLATFORM_DDD_STRATEGY.md),
> 보안 하드닝 [260702.006](260702.006.SECURITY_HARDENING.md).

---

## 0. 사전 준비
- **JDK 21** (베이스라인 고정). Maven 3.9.x(Wrapper 권장).
- **아티팩트 저장소 접근**: 사내 Nexus(release/snapshot)를 `~/.m2/settings.xml` 의 `<repositories>`/`<servers>` 에 등록.
  자가서명 인증서면 커스텀 truststore(`MAVEN_OPTS -Djavax.net.ssl.trustStore=...`) 필요.
- 좌표: 그룹 `ai.mutuus.common`, 현재 버전 `0.1.0-SNAPSHOT`.

## 1. 5분 온보딩 — 웹 서비스

### 1.1 pom.xml (핵심 3가지: parent · BOM import · starter 1개)
```xml
<parent>                                   <!-- 소비 서비스는 Boot 부모를 상속(독립 소비자 충실도) -->
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-parent</artifactId>
  <version>4.1.0</version>
</parent>

<dependencyManagement>
  <dependencies>
    <dependency>                            <!-- ① BOM import → 버전 없이 자사·optional 의존성 추가 -->
      <groupId>ai.mutuus.common</groupId>
      <artifactId>common-platform-bom</artifactId>
      <version>0.1.0-SNAPSHOT</version>
      <type>pom</type><scope>import</scope>
    </dependency>
  </dependencies>
</dependencyManagement>

<dependencies>
  <dependency>                              <!-- ② 스타터 1개 = 표준 웹 스택 전부 -->
    <groupId>ai.mutuus.common</groupId>
    <artifactId>common-platform-starter-web</artifactId>
  </dependency>
</dependencies>
```
`starter-web` 이 전이하는 것: `common-platform` + web · security · **oauth2-resource-server** · actuator · validation ·
restclient · **aspectj**(method-logging용) · **logstash-logback-encoder**(JSON 로깅). → 이것들을 개별 나열할 필요 없다.

### 1.2 로깅 활성화 (`src/main/resources/logback-spring.xml`)
```xml
<configuration>
  <property name="LOG_DIR" value="logs"/>            <!-- 운영: 로그 경로. 데모는 target/logs -->
  <include resource="logback-common.xml"/>           <!-- 라이브러리의 JSON 콘솔+롤링파일 appender -->
</configuration>
```
> 파일명은 자동으로 `<app-code>-<instance-code>.log`. `logstash-logback-encoder` 는 starter-web 이 이미 제공.

### 1.3 최소 설정 (`application.yml`)
```yaml
spring:
  application: { name: my-service }
  security:
    oauth2:
      resourceserver:
        jwt:
          jwk-set-uri: https://auth.mutuus.ai/realms/mutuus/protocol/openid-connect/certs   # 인증 MSA
mutuus:
  common:
    service-name: my-service
    app-code: MYSV                # 숫자/영문 4자리(미지정 시 service-name에서 결정적 도출)
    default-locale: ko-KR
    security:
      permit-all:                 # 인증 없이 열 경로(기본: /actuator/health/**,/actuator/info,/error)
        - /actuator/health/**
        - /api/public/**
```
> 인증은 **수행하지 않고 검증만** 한다(별도 인증 MSA 위임). `SecurityFilterChain`/`JwtAuthenticationConverter` 는
> `@ConditionalOnMissingBean` 이라 자체 빈을 정의하면 즉시 대체된다.

### 1.4 첫 컨트롤러 (표준 봉투)
```java
@RestController
class HelloController {
  @GetMapping("/api/public/hello")
  ApiResponse<Map<String,Object>> hello() {           // ApiResponse = 성공/오류 통합 봉투
    return ApiResponse.ok(Map.of("msg", "hi"));
  }
}
```
→ 실행 후 `/api/public/hello` 호출 시 응답에 `traceId`·표준 구조가 실리고, 콘솔에 JSON 액세스 로그가 남으면 온보딩 성공.

## 2. 즉시 켜지는 것 (out-of-the-box, 무설정)
스타터만 넣으면 자동으로:
- **e2e 추적**: `X-Trace-Id` 외 8개 헤더 인입/전파, 응답 회신, MDC 적재.
- **아웃바운드 전파**: Boot 자동구성 `RestClient.Builder`/`RestTemplateBuilder` 로 만든 클라이언트에 추적/식별 헤더 자동 부착.
- **API 생명주기 로깅**: `request.received`/`request.completed`(5xx·느린요청 WARN), 401/403 보안 로그, 예외 로깅.
- **표준 예외 응답**: `@RestControllerAdvice` 가 모든 예외를 `ApiResponse` 봉투로(4xx/5xx·검증·타임아웃 매핑).
- **i18n**: `MessageResolver` + `messages/messages*.properties`(기본/ko/en).
- **보안(자원서버)**: JWT 검증 + permit-all + 인증 주체를 감사/로그에 반영 + **보안 감사 로깅**(401/403).
- **관측 태그**: 모든 Observation 에 `service.name`.

## 3. 배치(비웹) 서비스 온보딩
```xml
<dependency>
  <groupId>ai.mutuus.common</groupId>
  <artifactId>common-platform-starter-batch</artifactId>   <!-- web/security 미전이(비전이 유지) -->
</dependency>
```
- `starter-batch` = `common-platform` + JSON 로깅만. **web/security 를 끌고 오지 않는다** → 비웹 서비스에 웹 자동구성이 붙지 않음.
- 추적/로깅/예외/i18n/이벤트/비동기 전파는 그대로 사용. 웹 전용 기능(TraceFilter·보안 체인)은 자동 비활성(조건부 자동구성).

## 4. 기능별 opt-in 카탈로그 (프로퍼티로 켜기)
필요한 것만 `mutuus.common.*` 로 켠다(대부분 기본 OFF — 오지랖 방지).

| 기능 | 토글 | 비고 / 필요 의존성 |
|---|---|---|
| 입출력 본문 로깅 | `payload-logging.enabled=true` | 로거 `...payload` |
| 컨트롤러 진입 로깅 | `controller-entry.enabled=true` + `packages` | 로거 `...controller` |
| 메서드 인자/리턴 로깅 | `method-logging.enabled=true` + `packages` | aspectj 필요(starter-web 제공) |
| 로그 민감정보 마스킹 | `logging.masking.enabled=true` | 카드/주민번호 등, 로그 한정 |
| 성공응답 자동 래핑 | `response-wrapper.enabled=true` | 컨트롤러가 `return dto;` 만으로 봉투 |
| 멱등성(Idempotency-Key) | `idempotency.enabled=true` | 분산 환경은 공유 저장소 빈 제공 |
| 캐시(Redis) | `cache.enabled=true` + `ttl` | `spring-boot-starter-cache`+`data-redis` 추가 |
| 다중 DataSource 라우팅 | `datasource.enabled=true` + `groups` | YAML로 read/write 라우팅 |
| 분산 세션(Redis) | (spring-session 추가 시) `session.*` | `spring-session-data-redis` 추가 |
| 영속 감사(BaseEntity) | (spring-data-jpa 시 기본 ON) `persistence.auditing-enabled` | `BaseEntity` 상속 |
| 도메인 이벤트 | 기본 ON `event.enabled` | in-process, 브로커는 확장점 |
| 보안 하드닝 | `security.audiences`·`trust-forwarded-user`·`csrf-enabled`·`headers.enabled` | [260702.006](260702.006.SECURITY_HARDENING.md) |

## 5. 표준 사용 패턴 (코드에서)
- **응답**: `ApiResponse.ok(data)` / 목록 `PageResponse.of(...)`(spring-data 는 `PageResponses.from(page)`).
- **에러(도메인 확장)**: `ErrorCode` 를 구현한 **자체 enum** + 자체 `messages` 번들, `throw new BusinessException(MyErrorCode.X)`.
  라이브러리를 건드리지 않고 동일 봉투/흐름으로 처리.
  ```java
  enum MyErrorCode implements ErrorCode { ORDER_NOT_FOUND(HttpStatus.NOT_FOUND, "error.order.notfound"); ... }
  ```
  `spring.messages.basename: messages/messages,messages/my-messages` 로 자체 번들 추가.
- **이벤트**: `eventPublisher.publish("Order.OrderPlaced", payload)` → 발행 시점 TraceContext 자동 주입(`DomainEvent`).
- **아웃바운드**: 주입받은 `RestClient.Builder` 로 만든 클라이언트는 무설정으로 추적/식별 헤더 전파.
- **감사**: `@Entity` 가 `BaseEntity` 상속 → `created_by`/`created_at` 등 자동(주체는 검증된 `X-User-Id`).

## 6. 온보딩 완료 체크리스트
- [ ] `starter-web`(또는 `-batch`) + BOM import, 개별 스택 나열 없음.
- [ ] `logback-spring.xml` 에 `logback-common.xml` include → 기동 시 JSON 로그 + `<app>-<instance>.log` 생성.
- [ ] `mutuus.common.service-name`(+ `app-code`) 설정.
- [ ] permit-all 경로 지정 + 그 외 요청은 JWT 필요.
- [ ] 컨트롤러가 `ApiResponse`/`PageResponse` 반환, 에러는 `ErrorCode`+`BusinessException`(수동 상태코드 금지).
- [ ] 사용자 노출 메시지는 `messages*.properties` 경유(하드코딩 금지).
- [ ] 스키마는 Flyway + `ddl-auto=validate`(엔티티 자동 DDL 금지) — 운영 원칙.
- [ ] 통합 검증(RANDOM_PORT)로 실제 소비 관점 테스트.

## 7. 자주 겪는 함정 (troubleshooting)
- **기동 시 `ClassNotFoundException: net.logstash...`** → `logback-common.xml` 은 logstash 인코더 필요. `starter-web` 이 제공하나, 직접 lib 만 의존했다면 `logstash-logback-encoder` 추가(버전은 BOM).
- **비웹 서비스에 웹/보안이 끌려옴** → `starter-web` 대신 `starter-batch` 사용.
- **`SchemaManagementException`(validate 실패)** → Flyway 마이그레이션과 엔티티 매핑 불일치. 새 컬럼은 **새 Flyway 버전**으로 추가(적용된 마이그레이션 수정 금지).
- **401 인데 로그에 사유가 없음** → 보안 감사 로거 `ai.mutuus.common.security.audit` 레벨 확인(기본 WARN).
- **감사 `created_by` 가 위장값** → 인입 `X-User-Id` 는 기본 미신뢰(`trust-forwarded-user=false`); 게이트웨이 신뢰망이면 true.
- **springdoc(OpenAPI) 필요** → `springdoc-openapi-starter-webmvc-ui` 추가(버전 BOM). 공통 OpenAPI 빈이 Bearer 보안 스킴 제공.
- **모듈러 모놀리스(Modulith)로 구성** → BOM 이 `spring-modulith-bom` 을 import 하므로 `spring-modulith-starter-core`/`-events-jpa` 등을 버전 없이 추가. 통합은 [260702.010](260702.010.MODULITH_INTEGRATION.md).
