# Sample Port Policy

`sample-api` uses a small fixed port block only for manual sample execution.

## Assigned Ports

| Purpose | Profile | Port |
| --- | --- | --- |
| Current/manual sample | default or `local` | `8090` |
| Sample test slot 1 | `ai` default | `8095` |
| Sample test slot 2 | `ai` override | `8096` |
| Sample test slot 3 | `ai` override | `8097` |
| Sample test slot 4 | `ai` override | `8098` |
| Sample test slot 5 | `ai` override | `8099` |

## Configuration

Default sample runtime:

```yaml
server:
  port: ${SAMPLE_API_PORT:8090}
```

Manual/background test runtime:

```yaml
server:
  port: ${SAMPLE_API_TEST_PORT:8095}
```

## Run Examples

Current sample:

```powershell
.\mvnw.cmd -pl samples/sample-api spring-boot:run
```

Test sample on the default test slot:

```powershell
.\mvnw.cmd -pl samples/sample-api spring-boot:run -Dspring-boot.run.profiles=ai
```

Test sample on another assigned test slot:

```powershell
.\mvnw.cmd -pl samples/sample-api spring-boot:run -Dspring-boot.run.profiles=ai -Dspring-boot.run.arguments="--SAMPLE_API_TEST_PORT=8096"
```

## Automated Tests

JUnit integration tests should keep using `RANDOM_PORT` unless a test explicitly validates the fixed-port convention. This avoids colliding with local services.

Guards:

- `AiProfilePropertiesTest`: verifies the `ai` profile default port and port metadata.
- `SamplePortPolicyTest`: verifies file-level default/test port policy without opening sockets.
