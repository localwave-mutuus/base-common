# 화면 메타데이터 공통화 후속

APP 인계 `handoff-wave18-logging-101-to-104-105.md`의 공통 소유 후속이다. 현재 배포/seed 대상0.2.5에는추가하지 않으며, 별도후속브랜치의0.2.6-SNAPSHOT 소스다. 게시·install·소비버전변경은미실행이다.

| 선택 헤더 | 로그에 싣는 형식 |
|---|---|
| X-Screen-Catalog-Version | yyyy-mm-dd.n(숫자 연월일 모양과 literal dot, 달력/카탈로그 존재 검증은 아님) |
| X-Business-Screen-No | 대문자3자-숫자3자 |
| X-Internal-Screen-Id | GM-SCR-숫자6자 |

core `ScreenMetadata.fromHeaders`가검증된불변Map을만든다. 값은64자이하만로그에싣고, 공백/개행/잘못된형식은생략한다. 오류를HTTP거부나업무입력판정으로변환하지않는다. 값은클라이언트주장메타데이터이며인증/인가근거가아니다.

TraceFilter는MDC와TraceContext에3필드를보강하고finally에서문맥을정리한다. 가장앞의AccessLogFilter는같은utility로검증값을수신시스냅샷하여http.request.in/http.response.out에직접싣는다. 따라서401보안거부, TraceFilter정리뒤, AsyncListener종료콜백도동일한3필드를갖는다. 기존X-Screen-Id/Event-Id처리는유지한다. 외부전파/응답헤더추가는없다.

APP/MEM/BO에별도필터나로깅클래스를추가하지않는다. 게시후공통의존버전만올리면적용된다. 소비sample의ScreenMetadataLoggingTest가형식·구형호환·문맥정리·동기짝·401·async중복완료·다음요청유출없음·잘못된선택헤더의202처리와JSON보존/생략을검증한다. 자체검증이며독립리뷰는별도다.
