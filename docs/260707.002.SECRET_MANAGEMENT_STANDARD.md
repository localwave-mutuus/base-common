# Secret Management Standard

This is the canonical secret-management standard for `common-platform` consumers.

## Decision

- Keep real secret values outside the repository.
- Do not commit runtime secret files, plaintext passwords, service tokens, or Nexus/admin credentials.
- Use Spring Boot native `spring.config.import` to load external runtime secret files.
- Keep the common library free of secret-manager client dependencies.
- The common library provides diagnostics only: `SecurityConfigAuditor` emits `security.config.secret_in_classpath_config` when secret-like values are found in classpath `application*.yml/properties`.

## Runtime Contract

Local sample runtime imports:

```yaml
spring:
  config:
    import: optional:file:${user.home}/.mutuus/${spring.application.name}/local.yml
```

For `sample-api`, the external file path is:

```text
${user.home}/.mutuus/sample-api/local.yml
```

The external file may contain:

```yaml
spring:
  datasource:
    password: "<local database password>"
  data:
    redis:
      password: "<local redis password>"
```

## Local File Workflow

Create the external file outside the repository:

```powershell
New-Item -ItemType Directory -Force $HOME/.mutuus/sample-api
Copy-Item samples/sample-api/secrets/local.example.yml $HOME/.mutuus/sample-api/local.yml
```

Edit only the copied runtime file:

```powershell
notepad $HOME/.mutuus/sample-api/local.yml
```

## Boundaries

- DB-backed configuration must not store bootstrap secrets such as datasource passwords. A DB password cannot safely be fetched from the DB it unlocks.
- Environment variables are acceptable as a short-lived CI bridge, but file mounts or platform secret injection are preferred.
- Docker/Kubernetes should mount a runtime secret file or use native secret projection, then point `spring.config.import` at that file.
- OpenBao or another secret manager can be added later for HA, leasing, audit, and rotation. That is an operations/runtime concern, not a direct dependency of the common jar.

## Common Module Responsibility

`common-platform` owns:

- Secret policy diagnostics in `SecurityConfigAuditor`.
- Documentation of the runtime contract.
- Sample/test/demo coverage proving consumers can externalize secrets without changing library code.

`common-platform` does not own:

- Secret rotation or vault unseal workflows.
- Runtime secret-manager SDK coupling.

## Verification

- Unit: `SecurityConfigAuditorTest` verifies classpath plaintext secret warnings.
- Policy: `SecretManagementPolicyTest` verifies `application-local.yml`, `.gitignore`, the sample local secret example, and this document.
- Manual screen: `/demo/index.html` includes `secret-policy`; the backing API is `GET /demo/secret-policy`.

## Migration Checklist

- Remove plaintext `password:` values from checked-in `application*.yml`.
- Add `spring.config.import` for an external runtime secret file.
- Add a non-secret example file and keep real runtime secret files outside git.
- Add ignore rules for runtime yml secret files.
- Run the policy tests and inspect `/demo/secret-policy` in the sample UI.
