## 점검 요약

기본 계층/패턴(Controller→Service→Repository, record DTO+MapStruct+Bean Validation, ApiResponse/PageResponse/ErrorCode)은 갖춰졌다. 다만 **상용 원천 소스** 기준으로는 아래가 부족하다 — 특히 **테스트 부재·스키마 관리·입력 방어**.

## P3 — 선택(운영 확장)

| # | 항목 | 내용 | 상태 |
|---|---|---|---|
| 12 | **낙관적 락(@Version)** | 동시 수정 충돌 방지(게시판 수정 시) | ✅ **완료** — 3스택 공통 `version` 컬럼 + 수정 시 `?version=` 로 낙관적 락. JPA `@Version`(jakarta)·JDBC `@Version`(spring-data)·jOOQ 는 조건부 `UPDATE ... WHERE version=?` 원자적 처리. 클라이언트 version 불일치 → 서비스가 `STALE_UPDATE`(409), flush/commit 시점 진짜 레이스 → `BoardExceptionAdvice` 가 `OptimisticLockingFailureException`→409 로 번역. 회귀 가드 `BoardOptimisticLockIntegrationTest`(3스택) + `board.html` 편집 시 version 전달·409 처리 |
| 11 | **jOOQ codegen** | 동적 API(부분 타입안전) → `jooq-codegen`(빌드타임 생성)로 완전 컴파일 타임 타입 안전성. 운영 권장 | ✅ **완료** — `jooq-codegen-maven` 이 `DDLDatabase` 로 **Flyway 스크립트(V1~V3)에서 라이브 DB 없이** board 테이블/컬럼 코드를 생성(`target/generated-sources/jooq`, 패키지 `...board.jooq.gen`). `BoardJooqDao` 를 생성 상수(`BOARD_POST.TITLE` 등) 기반으로 재작성 → 컬럼 오타/타입 오류가 컴파일 타임에 잡힘. timestamp 컬럼은 `forcedType` 으로 Instant 매핑, `defaultNameCase=lower` 로 H2/PG 이식. `BoardJooqConfig` 로 `renderQuotedNames=NEVER`(H2 UPDATE SET 의 따옴표+한정 컬럼 미지원 회피) |
| 13 | **미세 최적화** | JDBC `existsById`+`deleteById`(2쿼리) 등 정리 | ✅ **완료** — JDBC 삭제를 `@Modifying @Query("delete ...")` 단일 쿼리(`deleteByIdReturningCount`)로 합쳐 반영 0건이면 `POST_NOT_FOUND`(jOOQ DAO 와 동일 관용구). **부수 개선**: Flyway FK 도입으로 "자식(좋아요/댓글) 있는 글 삭제 → FK 위반 500" 버그가 드러나, `V3__board_fk_on_delete_cascade.sql`(이미 적용된 V1 을 고치지 않고 새 버전으로 진화 — Flyway 원칙)로 `on delete cascade` 부여해 3스택 공통 해결. 회귀 가드 `BoardBusinessValidationIntegrationTest` 에 삭제→200·재조회 404 추가 |

> **Flyway 도입 설계·검증 노트**: (1) **Boot 4 모듈 분리** — Flyway 자동구성이 `spring-boot-flyway` 로 분리돼(cache/restclient 처럼) `flyway-core` 만으론 자동실행이 안 된다 → `spring-boot-starter-flyway` 필요. (2) **DB별 모듈** — Flyway 10+ 는 DB 지원을 모듈화, PostgreSQL 17 은 `flyway-database-postgresql` 필요(H2 는 core 내장). (3) **DDL 이식성** — Hibernate 가 생성한 스키마를 기준으로 삼아(validate 정합 보장) H2·PG 공통 타입(`timestamptz`·`generated as identity`)으로 작성. (4) **다중 DS 라우팅과 공존** — Flyway 는 `@Primary` DataSource(app 그룹, `LazyConnectionDataSourceProxy`+라우팅 래핑)에 마이그레이션한다(db1/db2/db3 는 DB 랩이 프로그램적으로 만드는 별도 DataSource 라 Flyway 비대상). **검증**: H2 통합테스트(169 green) + **실 PostgreSQL 17.10**(`PostgresLiveAuditingIntegrationTest` — Flyway 가 실 PG 에 마이그레이션 후 감사 검증) + ai 프로파일 라이브 기동 3-스택 CRUD/락 스모크. → 원래 "PG 검증 갭"으로 남기려던 부분이 실 PG 로 **닫혔다**.

> **jOOQ codegen 설계·함정 노트**: (1) **라이브 DB 불요** — `org.jooq.meta.extensions.ddl.DDLDatabase` 가 Flyway 마이그레이션 스크립트를 파싱해 메타데이터를 뽑으므로, 빌드 시 DB 접속 없이 `generate-sources` 단계에서 코드가 생성된다(`sort=flyway` 로 V1→V3 순 적용, ALTER 의 FK cascade 까지 반영). (2) **Boot 4 모듈** — Flyway 처럼 jOOQ 자동구성도 `spring-boot-jooq` 모듈(`org.springframework.boot.jooq.autoconfigure`)로 분리됐다. (3) **타입/이식성** — `forcedType` 으로 `timestamp with time zone`→`Instant`(도메인 정합), `defaultNameCase=lower` 로 소문자 렌더(H2 CASE_INSENSITIVE·PG 공통). (4) **H2 UPDATE 함정(중요)** — 생성 `TableField` 는 `"board_post"."title"`(따옴표+한정)로 렌더되는데 **H2 는 UPDATE 의 SET 절에서 이 형태를 거부**한다(원본 동적 DAO 는 비한정 `"title"` 이라 통과했음). `RenderTable` 설정으로는 해결 안 되고, `Settings.renderQuotedNames=NEVER`(따옴표 제거)로 대소문자 무시 매칭이 되어 해결된다 — `BoardJooqConfig` 의 `DefaultConfigurationCustomizer` 로 적용. **검증**: 전 통합테스트 169 green(3스택 CRUD·검색·낙관적 락·삭제 cascade).

> **@Version 낙관적 락 설계 노트**: JPA/JDBC 는 프레임워크의 `@Version` 에 위임(수정 시 `version` 검사·증가·flush), jOOQ 는 코드젠 없는 동적 API 라 DAO 가 직접 `WHERE id=? AND version=?` + `SET version = version+1` 로 <b>원자적 조건부 갱신</b>(반영 0건이면 버전 불일치)한다. 세 방식 모두 결과적으로 동일한 계약(있으면 검사, null 이면 미검사)으로 수렴한다. JPA 는 `save()` 직후가 아니라 flush 시점에 version 이 증가하므로 응답에 증가값을 담으려면 `saveAndFlush` 가 필요하다.

## 권장 실행 순서

1. **P1 일괄**(테스트·Flyway·파라미터 방어·NPE) — 원천 소스의 신뢰성 확보. 특히 #1 테스트는 이후 리팩터링의 안전망.
2. **P2**(이스케이프·이식성·DTO 순수성·감사·OpenAPI·엔티티 규약) — 모범사례 완성도.
3. **P3**(codegen·락) — 운영 확장 시.

> 각 개선은 3스택 **동시에** 반영(원천 소스 일관성) + 회귀 가드 추가 + 이 문서/가이드 갱신 + 데모 화면 재검증(31/31 + 게시판 3종) 원칙.
