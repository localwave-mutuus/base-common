# 0.3.0 HTTP 상관키와 오류 본문 관측

HTTP 수신은 기존 X-Trace-Id·trace.id·span.id를 유지하고, 수신 X-Span-Id를 parent.id로 기록한다. traceparent만 있는 요청도 유효한 W3C 00 형식이면 수용한다. 서비스 span은 요청마다 새로 만들며 하위 HTTP에는 현재 서비스 span을 전달한다. 따라서 하위 parent.id와 상위 span.id를 대조할 수 있다. 응답 X-Trace-Id는 유지한다.

RestClient/RestTemplate 전파의 기존 신뢰 호스트 정책은 유지한다. java.net.http 호출은 ai.mutuus.common.core.TraceHeaders.apply(builder)를 사용한다. trace가 기존 비표준 형식이면 X-*는 유지하되 잘못된 traceparent를 만들지 않는다. W3C 전파는 mutuus.common.tracing.w3c=false로 끈다.

본문 로깅은 mutuus.common.payload-logging.enabled=false가 기본이며 소비 서비스에서 켜지 않는다. 필요한 경우에만 enabled=true와 mode=error-only를 함께 명시한다. 요청·응답 기록의 기본 및 최대 상한은 각각4096바이트다. allowed-headers만 기록하며 Authorization, Proxy-Authorization, Cookie, Set-Cookie는 목록에 넣어도 제외한다. 이전 enabled=true 사용자의 ALL 모드는 유지한다. 본문 로깅 전체 중지는 enabled=false다.

게시 좌표는 ai.mutuus.common 그룹의 common-platform-parent, common-platform-bom, common-platform, common-platform-starter-web, common-platform-starter-batch 모두0.3.0이다. 되돌림은 소비 서비스 BOM/스타터를0.2.9로 복구한 뒤 기존 배포 절차로 재배포한다. Gate 변경은 이전 nginx 설정 커밋으로 되돌린다.

단위검증은 samples/sample-api에 두며 HTTP parent 전달, W3C 잘못된 입력/끄기, MDC 정리, 오류 전용/응답 보존/크기/헤더 제한을 확인한다. async ThreadLocal 복원의 단위 확인은 실제 이벤트 재발행·Redis 중계나 DEV 상관 성공을 보증하지 않는다. 해당 경로와 §4.2 합동 DEV 검증은 UNPROVEN이며 총괄 담당이 별도 수행한다.
