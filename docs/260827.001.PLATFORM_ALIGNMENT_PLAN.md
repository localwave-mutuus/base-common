## 4. 우선순위와 순서

```
Phase 0 (공급 경로)  ─┬─> Phase 1 (저장소 동기화)  ─┬─> Phase 3 (승격 → 0.3.0)
                      │                              │
                      └─> Phase 2 (문서 편차)  ──────┘
```

- **Phase 0과 2는 병렬 가능**하다. 0은 인프라·의사결정 대기가 있고, 2는 즉시 착수 가능한 문서 작업이다.
- **Phase 3은 0·1 완료 후**에 착수한다. 게시 경로가 끊긴 채로 0.3.0을 만들면 소비 서비스가 받을 방법이 없다.
- 착수 즉시 가능한 최소 단위는 **2-1~2-4**(문서 4건)다.

## 8. AI 변경관리 지침

- 본 문서는 **계획의 정본**이다. 항목을 완료하면 체크리스트를 갱신하고, 갭 표의 해당 행에 완료 커밋 해시를 남긴다.
- 갭 판정은 **문서 대조가 아니라 코드 실측**으로 한다. 소비 서비스 pom 주석에 남은 실측 근거(`-jdbc` 전환, observability 제거)가 그 예다.
- 승격(Phase 3) 시 소비자 구현을 **재설계하지 않는다**. 운영 검증된 코드와 그 테스트를 함께 옮기고, optional 의존성 + 조건부 자동구성 패턴(CLAUDE.md §1)을 지킨다.
- 소비 서비스에서 공통모듈 결함이나 문서 오류를 새로 발견하면 이 문서의 갭 표에 ID를 부여해 추가한다.
- 본 문서에 평문 비밀번호·토큰·계정 자격은 쓰지 않는다([docs 작성 규칙](README.md)).
