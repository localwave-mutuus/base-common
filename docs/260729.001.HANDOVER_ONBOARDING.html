1.프로젝트 정체성 (모든 설계 결정의 근간)

  • 핵심 산출물은 단일 jar 공통 라이브러리 ai.mutuus.common:common-platform임. 실행 애플리케이션이 아니라 소비 서비스에 흡수되는 라이브러리임.
  • 타 API 서비스가 Maven 의존성 하나(스타터)로 추적/로깅/예외/i18n/인증/세션/캐시/멱등성 기능을 재사용함.
  • 이 레포의 모든 코드·설정·문서는 상용(운영) 품질 AI 코딩의 모범사례이자 원천 소스(source of truth)로 관리함 — 임시방편·"일단 동작" 코드를 남기지 않음.
  • 현재 버전: 0.2.1 (릴리스 커밋 63ebfad). 기준 런타임: Java 21 / Spring Boot 4.1.0 (Framework 7) / Spring Modulith 2.1.0.
브랜치명(appmod/java-upgrade-*)이나 일부 커밋에 "Java 25"가 보여도 산출물 타깃은 JDK 21 고정임 (안정성·소비 서비스 강제 회피를 이유로 되돌림 — parent/pom.xml의 java.version).

2.제공 기능 및 역할 (소비 서비스 관점)

공통모듈의 역할은 다섯 가지임: (1) 관측성 표준화(추적·로깅), (2) 응답/예외 규약 통일, (3) 보안 기본기 위임 수용(JWT 검증·감사), (4) 인프라 컨벤션(세션·캐시·DataSource·멱등성), (5) 버전 거버넌스(BOM). 소비 서비스는 스타터 1개로 아래 기능을 받음.

  • lib/pom.xml의 spring-boot-maven-plugin은 <skip>true</skip> — 라이브러리라 repackage하지 않음. 건드리지 말 것.

6.반드시 지켜야 하는 설계 원칙 (위반 = 회귀)

1. optional 의존성 + 조건부 자동구성 — 통합 의존성은 전부 lib/pom.xml에서 <optional>true</optional>, 자동구성은 @ConditionalOnClass(+@ConditionalOnProperty/@ConditionalOnMissingBean) 보호. 비웹 배치 소비자에 web/security가 끌려가면 안 됨 — sample-batch가 이걸 검증함.
2. 소비자 설정 우선 — 컨벤션 기본값은 CommonEnvironmentPostProcessor에서 addLast로만 주입. 소비 서비스 application.yml이 항상 이김.
3. 테스트 위치 — 모든 테스트는 samples/*에서 수행. lib/src/test는 두지 않음(현재 0개). 라이브러리 내부 단위 테스트도 sample-api에 같은 패키지명(ai.mutuus.common.*, classpath split-package)으로 둠.
4. ThreadLocal 정리 규율 — TraceContext/RoutingContext는 finally에서 반드시 clear() (누수 방지).
5. 소비자 대체 가능성 — 라이브러리 빈은 @ConditionalOnMissingBean으로 소비자 자체 빈에 비켜섬. 새 빈도 이 패턴을 따름.
6. i18n·한국어 — 노출 메시지는 messages*.properties+MessageResolver 경유, 주석·문서·응답은 한국어.
7. 문서 명명 규칙 — docs/yymmdd.NNN.<제목>.md. 문서 추가/개명 시 README 색인 등 모든 참조 링크 동시 갱신.

7.빌드·테스트·배포

Maven Wrapper(3.9.9 고정) 포함 — JDK 21만 있으면 됨.

.\mvnw.cmd -pl lib clean install     # 라이브러리만 (대부분의 lib 작업은 이걸로 충분)
.\mvnw.cmd clean install             # reactor 전체: parent→bom→lib→starters→samples(테스트 포함)
.\mvnw.cmd clean test                # reactor 전체 테스트
함정 1 — 샘플 단독 실행: cd samples/sample-api && ..\..\mvnw.cmd test는 lib를 .m2 jar로 해석함. lib API를 바꿨으면 먼저 -pl lib install 후 샘플에서 반드시 clean (stale .class → NoSuchMethodError). 루트 reactor 실행이면 이 함정이 없음.
함정 2 — Windows/VS Code: 전체 reactor 빌드 중 VS Code(jdt.ls)가 target/을 잠가 간헐 실패할 수 있음 — VS Code를 닫거나 재시도.

Docker 없는 환경: Testcontainers 테스트는 자동 skip. 로컬 실 인프라 대상 *LiveIntegrationTest는 support/LiveInfra 게이트(접속+인증 성공 시에만 실행)로 opt-in.

배포(사내 Nexus 3) — self-signed라 truststore 지정 필요:

$env:MAVEN_OPTS='-Djavax.net.ssl.trustStore=C:\Users\cvnra\.m2\nexus-local-ca-truststore.p12 -Djavax.net.ssl.trustStorePassword=changeit -Djavax.net.ssl.trustStoreType=PKCS12'
.\mvnw.cmd clean deploy
