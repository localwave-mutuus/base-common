# DB-backed Configuration Plan

## 목표

파일 기반 `application.yml`과 프로파일 설정은 유지하되, 운영 중 서비스별로 중앙 관리해야 하는 프로퍼티를 DB에서 공급한다. 공통모듈의 원칙은 그대로 유지한다.

- 공통모듈은 단일 jar 라이브러리다.
- DB-backed configuration은 optional 기능이어야 한다.
- 소비 서비스가 파일로 명시한 값은 공통 기본값보다 우선한다.
- DB 설정 실패 시 fail-fast 또는 file fallback을 명시적으로 선택할 수 있어야 한다.
- 테스트는 고정 포트 서버나 공유 인프라를 건드리지 않는다.

## 부트스트랩 제약

DB에서 설정을 읽으려면 DB 접속 정보가 먼저 필요하다. 따라서 모든 설정을 DB로만 옮길 수는 없다. 다음 값은 bootstrap source에 남긴다.

- `spring.application.name`
- active profile
- DB config repository 접속 정보 또는 이미 등록된 `DataSource` 선택 정보
- DB config enable 여부와 실패 정책

bootstrap secret은 DB에 저장하지 않는다. 로컬 개발은 SOPS + age로 복호화한 외부 파일을 쓰고, CI/CD와 운영은 해당 플랫폼의 secret store 또는 secret mount를 사용한다.

## 권장 설정

소비 서비스는 최소 설정만 파일 또는 외부 import로 둔다.

```yaml
spring:
  config:
    import: optional:file:${user.home}/.mutuus/${spring.application.name}/local.yml

mutuus:
  common:
    config-db:
      enabled: true
      fail-fast: false
      application: ${spring.application.name}
      profile: ${spring.profiles.active:default}
```

외부 secret 파일 예:

```yaml
mutuus:
  common:
    config-db:
      source:
        url: jdbc:postgresql://<host>:12556/golmok?sslmode=require
        username: <user>
        password: <secret>
```

## DB 스키마

PostgreSQL `golmok` 안에서는 `configuration` schema가 설정 테이블을 소유한다.

```sql
create schema if not exists configuration;

create table if not exists configuration.common_config_property (
  id bigint generated by default as identity primary key,
  application varchar(100) not null,
  profile varchar(100) not null,
  property_key varchar(300) not null,
  property_value text,
  value_type varchar(40) default 'string',
  encrypted boolean default false,
  enabled boolean default true,
  version bigint default 0,
  updated_at timestamp with time zone,
  updated_by varchar(100),
  constraint uq_config_property unique (application, profile, property_key)
);
```

조회 우선순위:

1. `application=<service>, profile=<active>`
2. `application=<service>, profile=default`
3. `application=common, profile=<active>`
4. `application=common, profile=default`

## Spring 통합 방식

초기 로딩에 필요한 설정이므로 `EnvironmentPostProcessor`보다 Spring Boot `ConfigData` 확장이 적합하다.

사용자는 다음처럼 import한다.

```yaml
spring:
  config:
    import: optional:mutuus-dbconfig:
```

구현 후보:

- `ConfigDataLocationResolver`
- `ConfigDataLoader`
- DB 조회 결과를 `MapPropertySource`로 변환

이 방식이면 `@ConfigurationProperties`와 `@ConditionalOnProperty` 평가 전에 DB 설정이 들어온다.

초기 버전은 시작 시 1회 로딩만 제공한다. 운영 중 동적 변경은 별도 단계로 분리하고 Actuator endpoint, polling, cache invalidation 중 하나로 확장한다.

## 우선순위 정책

권장 우선순위:

1. 명령행 인자, 시스템 프로퍼티, 환경변수
2. 소비 서비스 파일 설정
3. DB 설정
4. 공통 라이브러리 기본값

즉 DB 설정은 공통 기본값보다 강하지만 배포자가 명시한 파일/환경 설정보다 약하다. 장애 시 즉시 override할 수 있어야 하기 때문이다.

운영에서 DB 설정을 파일보다 강하게 만들고 싶다면 별도 opt-in인 `mutuus.common.config-db.override-file=true`를 둔다.

## 보안 정책

- bootstrap 비밀값은 DB에 저장하지 않는다.
- 평문 비밀번호, age private key, Nexus/admin credential은 커밋하지 않는다.
- 로컬 개발은 [260707.002.SECRET_MANAGEMENT_STANDARD.md](260707.002.SECRET_MANAGEMENT_STANDARD.md)의 SOPS + age 방식을 따른다.
- DB에 저장하는 설정 중 민감값은 `encrypted=true`로 표시하고, 복호화 SPI는 후속 단계에서 붙인다.
- 모든 로딩 결과에는 application/profile/property count/version을 구조화 로그로 남긴다.

## 구현 단계

1. `lib`에 `config/db` 패키지 추가: `DbConfigProperties`, `DbConfigRepository`, `DbConfigPropertySource`.
2. JDBC 관련 의존성은 optional로 유지한다.
3. `mutuus-dbconfig:` ConfigData import 제공.
4. 샘플은 PostgreSQL 기반 config table을 만들고, DB 설정이 공통 기본값보다 우선 적용되는지 검증한다.
5. DB unavailable + `fail-fast=false`면 부팅 성공, `fail-fast=true`면 부팅 실패 테스트를 추가한다.
6. encrypted value 복호화 SPI는 별도 보안 확장으로 추가한다.

## 테스트 계획

- `ApplicationContextRunner`: DB config disabled 기본 비활성 검증.
- mock repository 또는 PostgreSQL Testcontainers: property source 로딩 단위 검증.
- `sample-api` MOCK 웹 컨텍스트: DB 설정값이 `@ConfigurationProperties`와 `@ConditionalOnProperty`에 반영되는지 검증.
- live PostgreSQL 검증: 명시 opt-in일 때만 `golmok` 대상 수행.
- 고정 포트 서버와 공유 Redis/PostgreSQL 키 삭제는 사용하지 않는다.
