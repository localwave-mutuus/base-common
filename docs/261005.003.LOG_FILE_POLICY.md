# 프로젝트별 로그 설정 표준 — 0.2.6

각 프로젝트는 JAR의 `logback-standard-template.xml`을 자기 `logback-spring.xml`로 복사한다. 이 파일은 자동 적용되지 않는다. 레벨, 로거, JSON 콘솔/파일 구성은 프로젝트가 소유하며 표준과 다른 설정마다 이유를 한 줄 주석으로 남긴다. 공통 클래스(HTTP/작업 짝 API, 인코더, 닫힌 파일 굴림, 종료 close)를 그대로 사용하고 프로젝트에 로깅 클래스를 만들지 않는다. 기존 `logback-common.xml` include는 이전 소비자의 호환 용도로 남긴다.

```yaml
mutuus:
  common:
    service-short-name: member # app/member/bo/batch
    logging:
      file:
        roll-interval: PT1H
        max-file-size: 100MB
```

환경변수 `GS_LOG_ROLL_INTERVAL`, `GS_LOG_MAX_FILE_SIZE`가 해당 YAML 값보다 우선한다. 미지정 기본은 PT1H/100MB. 이전 `mutuus.log.roll-interval`은 canonical 값 미지정 때만 사용한다. 모든 값은 로깅 초기화 전 검증되며 부정확한 값은 해당 설정 이름을 포함하는 기동 오류다. 크기는 양의 정수 B/KB/MB/GB/TB(1024 배수)이며 단위 생략은 B다.

굴림 간격은 ISO-8601 duration, PT1M..PT24H 범위 **및 1시간의 약수** 조건을 모두 만족해야 한다. 따라서 PT5M/PT30M/PT1H는 허용하지만 PT7M/PT2H/PT24H는 거부한다(범위 상한만으로 허용되는 것이 아님). PT90S처럼 조건을 만족하는 초 단위도 허용한다. UTC 정각 기준 구간으로 굴리며 요청/작업 로그가 없는 동안에는 파일을 열어둔다. 다음 기록 또는 정상 종료가 굴림을 수행한다.

활성 이름 `<env>-<app>-<serial>-<pid>.log`는 수집하지 않는다. 닫힌 이름 `<...>.<yyyyMMdd-HH>.<n>.log.gz`만 수집한다. 같은 HH 안의 PT5M 굴림은 n 증가로 구분한다. 재시작 및 업로드 후 파일 삭제에도 순번 장부를 유지해 이름을 재사용하지 않는다. 종료 시 async 큐를 전부 비운 뒤 마지막 파일을 닫힌 이름으로 압축·원자 공개한다.

## 보관과 남긴 고정값

- PT1H/100MB는 변경 가능한 기본값이며 코드 강제 정책이 아니다. XML의 fallback도 동일하다.
- UTC/HH 표기, r5 이름, gzip close 후 원자 공개, 영속 순번은 수집 프로토콜이라 고정한다.
- PT1M..PT24H 및 1시간 약수 검증은 사용자 계약이라 고정한다.
- 로컬 파일 수/보관 기간 상한에 따른 삭제는 **없다**. 수집기만 S3 업로드 성공을 확인한 후 삭제한다(r2). 보관 수/기간을 프로젝트별로 바꿀 때도 수집기 설정에서 성공 확인을 보존해야 한다. S3 보관 정책은 인프라 소유이며 공통 JAR에서 변경하지 않는다.
- 기본 INFO/JSON, async queue 1024는 템플릿의 프로젝트 소유 설정이다. discard=0/neverBlock=false/maxFlushTime=0은 짝 누락 방지 설정으로 유지한다. 바꾸면 손실·정상 종료 보장을 별도로 검증한다.

DEV PT5M 환경변수 적용·제거와 DEV/PROD 승격은 각 환경 소유자/총괄 PM 책임이다. 이 릴리스는 해당 환경을 변경하지 않는다.
