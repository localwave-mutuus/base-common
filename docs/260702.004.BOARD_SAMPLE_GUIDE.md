# 게시판 3-스택 모범사례 샘플 — AI 코딩 참조 가이드

> **목적**: 이 문서와 `samples/sample-api` 의 `ai.mutuus.sample.board` 패키지는 **AI 코딩 어시스턴트가 참조하는
> Java(Spring Boot) 데이터 접근 모범사례 레퍼런스**다. 새 CRUD 기능을 만들거나 변경할 때 **이 샘플의 구조·관습을
> 따르고**, 아래 "AI 변경관리 지침" 대로 확장한다. 같은 도메인(게시판)을 **Spring Data JPA / jOOQ / Spring Data JDBC**
> 세 방식으로 구현해 스택별 관용구를 나란히 비교한다.

관련: DB 스택 선정 근거 [260702.002.DB_LAYER_GUIDE.md](260702.002.DB_LAYER_GUIDE.md) · 화면 <http://localhost:8081/demo/board.html>

---

## 1. 무엇을 보여주는가 (핵심 원칙)

1. **계층 분리**: `Controller`(HTTP·검증·표준봉투) → `Service`(트랜잭션·비즈니스규칙) → `Repository/DAO`(영속). 컨트롤러는 영속 기술을 모른다.
2. **DTO 는 Record**: 요청/응답은 불변 `record`(보일러플레이트 0). 엔티티를 API 로 직접 노출하지 않는다.
3. **매핑은 MapStruct**: 엔티티↔DTO 는 컴파일 타임 생성 매퍼. 필드 누락 시 컴파일 에러로 잡힌다.
4. **검증은 Bean Validation**: 요청 record 필드에 `@NotBlank`/`@Size` 등 선언. 실패 → 표준 400 + fieldErrors.
5. **공통 라이브러리 소비**: 응답은 `ApiResponse`, 목록은 `PageResponse`, 도메인 에러는 `ErrorCode` 구현 + `BusinessException`(→ 표준 404 등). 직접 상태코드/봉투를 만들지 않는다.
6. **조회 트랜잭션**: 서비스 클래스는 `@Transactional`(쓰기 기본), 조회 메서드는 `@Transactional(readOnly = true)`.

## 2. 패키지 구조

```
ai.mutuus.sample.board
├── dto/
│   ├── BoardPostRequest   (record + Bean Validation)  — 생성/수정 입력
│   └── BoardPostResponse  (record)                     — 응답(+ tech 라벨)
├── BoardService           (계약 인터페이스 — 세 구현이 공유)
├── BoardErrorCode         (ErrorCode 구현: POST_NOT_FOUND=404)
├── web/AbstractBoardController  (얇은 REST 공통 컨트롤러 — 영속 기술 무관)
├── jpa/    BoardPost(@Entity) · BoardPostJpaRepository · BoardJpaMapper · BoardJpaService · BoardJpaController
├── jooq/   BoardPostRow(record) · BoardJooqDao(DSLContext, jooq-codegen 생성 테이블 사용) · BoardJooqConfig(Settings)
│           · BoardJooqMapper · BoardJooqService · BoardJooqController · gen/(빌드 생성, target)
├── jdbc/   BoardPostJdbc(@Table) · BoardPostJdbcRepository · BoardJdbcMapper · BoardJdbcService · BoardJdbcController
└── (스키마) board_post/like/comment 테이블은 Flyway(src/main/resources/db/migration/V1__create_board_schema.sql)
             로 생성 — 세 스택이 공유. Hibernate 는 ddl-auto=validate 로 정합만 검증(운영급: 엔티티 자동 DDL 금지)
```

> **JPA/JDBC 공존**: `ai.mutuus.sample.board.BoardDataConfig` 가 `@EnableJpaRepositories`/`@EnableJdbcRepositories`
> 를 basePackages 로 분리해 두 Spring Data 모듈이 충돌하지 않게 한다.

## 3. 요청 흐름 (모든 스택 동일)

```
HTTP → AbstractBoardController(@Valid, 표준봉투) → BoardXxxService(@Transactional, find-or-throw)
     → Repository/DAO(영속) → MapStruct(엔티티→DTO) → ApiResponse/PageResponse
```
- 목록: `GET /demo/board/{stack}?keyword=&page=&size=` → `ApiResponse<PageResponse<BoardPostResponse>>`
- 단건: `GET .../{id}` (없으면 `BusinessException(POST_NOT_FOUND)` → 404)
- 생성/수정: `POST` / `PUT .../{id}` (검증 실패 → 400 fieldErrors)
- 삭제: `DELETE .../{id}`

## 4. 스택별 관용구 (같은 유스케이스, 다른 구현)

| 관점 | JPA | jOOQ | Spring Data JDBC |
|---|---|---|---|
| 영속 타입 | `@Entity BoardPost` | `record BoardPostRow` | `@Table BoardPostJdbc` |
| 조회/CRUD | `JpaRepository` 기본 메서드 | `DSLContext` + **codegen 생성 테이블**(`BOARD_POST.*`) | `ListCrudRepository` 기본 메서드 |
| 검색+페이징 | `@Query`(JPQL) + `Pageable` | 조건 + `limit/offset` + `count` | `@Query`(SQL) + `limit/offset` + `count` |
| 강점 | 생산성·선언적 쿼리 | 복잡/PG특화(JSONB·CTE·window·upsert) 타입세이프 | "마법" 최소·예측 가능한 SQL |
| 페이징 결과 | `Page` → `PageResponse.of(...)` | 수동 → `PageResponse.of(...)` | 수동 → `PageResponse.of(...)` |

**선택 기준**: 기본 CRUD·도메인 모델 중심 → JPA. 복잡한 분석/PG 특화 SQL → jOOQ. 단순·명시적 SQL 선호 → Spring Data JDBC.
(jOOQ 는 `jooq-codegen-maven` 이 Flyway 스크립트에서 테이블 코드를 빌드타임 생성 → `BOARD_POST.TITLE` 등 생성 상수로 **완전한 컴파일 타임 타입 안전성** 확보. 상세·함정은 [260702.005.BOARD_SAMPLE_IMPROVEMENTS.md](260702.005.BOARD_SAMPLE_IMPROVEMENTS.md) 의 jOOQ codegen 노트)

## 4.5 jOOQ 동적 쿼리 샘플 (동적 SELECT + 동적 WHERE)

jOOQ 의 강점(런타임에 SQL 을 프로그램적으로 조립)을 보여주는 **jOOQ 전용** 엔드포인트다(다른 스택엔 없음).
복잡 조건이라 `POST /demo/board/jooq/search` 본문({@code BoardSearchRequest})으로 받는다.

- **동적 WHERE(조건부 조립)** — `BoardJooqDao.dynamicCondition(...)` 이 `DSL.noCondition()` 에서 시작해 **값이 있는 조건만** `and` 로 누적한다:
  - `keyword` → 제목·작성자 **LIKE**(부분일치, `escapeLike` 로 와일드카드 이스케이프)
  - `authors` → 작성자 **IN** 목록
  - `createdFrom`/`createdTo` → 작성일시 **범위**(`ge`/`le`, 각각 생략 가능)
- **동적 SELECT(투영)** — `fields` 로 응답 컬럼을 고른다. `BoardJooqDao.FIELD_MAP`(논리명→생성 컬럼) **허용목록(allowlist)** 안에서만 허용해 임의 컬럼 주입을 막고, 각 행을 요청 필드명 순서의 `LinkedHashMap`(sparse fieldset)으로 반환한다.
- **계층/검증** — 컨트롤러는 얇게(위임), 서비스가 **의미 검증**(허용목록 밖 필드 → 400 `INVALID_SEARCH_FIELD`, 범위 역전 `from>to` → 422 `INVALID_SEARCH_RANGE`)과 정규화(키워드 이스케이프·작성자 공백 제거·페이징 클램프)를 한 뒤 DAO 에 위임. 응답은 `PageResponse<Map<String,Object>>`.
- 회귀 가드: `BoardDynamicSearchIntegrationTest`(LIKE/IN/범위/투영/400/422).

```jsonc
// POST /demo/board/jooq/search
{ "keyword": "공지", "authors": ["admin","alice"],
  "createdFrom": "2026-01-01T00:00:00Z", "createdTo": "2026-12-31T23:59:59Z",
  "fields": ["id","title","author","createdAt"], "page": 0, "size": 20 }
```

## 5. AI 변경관리 지침 (이 샘플을 고칠 때 / 새 기능을 만들 때)

- **필드 추가**(예: `views` 조회수):
  1. **새 Flyway 마이그레이션**(`V4__add_views.sql`)으로 `board_post` 에 컬럼 추가(이미 적용된 V1~V3 은 수정 금지).
     그리고 JPA `@Entity`·Spring Data JDBC `@Table` 에 필드 추가(둘 다 `ddl-auto=validate` 로 스키마와 정합 검증).
  2. `BoardPostRequest`/`BoardPostResponse` record 에 필드 추가. 3. `BoardPostRow` record 에도 추가.
  4. MapStruct 는 이름만 맞으면 자동 매핑(누락 시 컴파일 에러가 알려줌).
  5. jOOQ 는 `generate-sources` 재실행 시 새 컬럼 상수(`BOARD_POST.VIEWS`)가 자동 생성됨 → DAO 의 insert/select 목록에 그 상수 추가. JDBC `@Query` SQL 에 컬럼 추가.
- **엔드포인트 추가**: 공통이면 `AbstractBoardController` 에, 스택 특화면 해당 컨트롤러에. 비즈니스 로직은 반드시 **Service** 에 둔다(컨트롤러에 로직 금지).
- **새 도메인(게시판이 아닌 것)**: 이 패키지 구조(dto/service/repo + MapStruct + ErrorCode + ApiResponse/PageResponse)를 **그대로 복제**해 시작한다.
- **에러**: 새 실패 상황은 도메인 `ErrorCode` enum 에 항목 추가 + `messages/sample-messages*.properties` 키 추가 → `BusinessException` 으로 던진다. 컨트롤러에서 `ResponseEntity` 상태코드를 손으로 만들지 않는다.
- **테스트**: 통합 검증은 소비 서비스 샘플에서(리액터 규칙). 실 DB 동작은 화면(`/demo/board.html`) + 필요한 통합테스트로.

### Do / Don't (AI)
- ✅ 컨트롤러는 얇게(검증·매핑·위임만) · 로직은 Service · 트랜잭션은 Service 경계.
- ✅ 요청/응답은 record · 엔티티 직접 노출 금지 · 매핑은 MapStruct.
- ✅ 목록은 `PageResponse`, 오류는 `ErrorCode`+`BusinessException`, 응답은 `ApiResponse`.
- ❌ 컨트롤러에서 DB/영속 타입 직접 사용, 수동 상태코드 생성, `any`/`Map` 남발.
- ❌ 엔티티를 요청/응답 타입으로 그대로 사용.

## 6. 회귀/검증

- 빌드: 리액터 `clean install`(sample-api 컴파일에 MapStruct 프로세서 동작).
- 화면: `/demo/board.html` — 3탭(JPA/jOOQ/JDBC) 각각 목록·검색·페이징·상세·글쓰기·수정·삭제가 **실 DB(board_post)** 로 동작.
- 검증 포인트: 생성→목록 노출, 키워드 검색, 페이지 이동, 상세 조회, 수정 반영, 삭제 후 404, 빈 제목 → 400(fieldErrors).
