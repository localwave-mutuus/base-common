# GitHub Packages Maven 배포 및 소비

이 저장소의 배포 산출물은 Git 저장소에 `jar`를 커밋하는 방식이 아니라 GitHub Packages의 Maven Registry에 게시한다. 따라서 타 프로젝트는 일반 Maven 의존성과 동일하게 `common-platform`, BOM, 큐레이션 스타터를 해석할 수 있다.

## 게시 대상

`parent`, `bom`, `lib`, `starters/starter-web`, `starters/starter-batch`가 게시된다. `samples/*`와 루트 aggregator는 `maven.deploy.skip=true`로 게시하지 않는다. 기존 Nexus 배포는 기본값으로 유지되며, GitHub Packages는 `github` 프로필로 선택한다.

## 자동 게시

`v*` 태그를 push하거나 GitHub Actions의 `workflow_dispatch`를 실행하면 `.github/workflows/publish-github-packages.yml`이 다음을 수행한다.

1. JDK 21과 Maven Wrapper를 준비한다.
2. reactor 전체를 테스트하고(`clean deploy`) 테스트가 성공한 경우에만 게시한다.
3. `GITHUB_TOKEN`을 사용해 `https://maven.pkg.github.com/localwave-mutuus/base-common`에 게시한다.

새 버전은 모든 게시 모듈의 버전을 함께 올리고, 예를 들어 `v0.2.4` 태그를 push한다. 이미 게시된 동일 버전은 GitHub Packages의 immutable version 정책으로 다시 덮어쓸 수 없으므로 새 버전을 사용한다.

## 수동 게시

로컬에서는 GitHub 사용자명과 Packages write 권한의 토큰을 Maven `settings.xml`의 `github` 서버에 넣은 뒤 실행한다.

```xml
<settings>
  <servers>
    <server>
      <id>github</id>
      <username>GITHUB_USERNAME</username>
      <password>GITHUB_TOKEN</password>
    </server>
  </servers>
</settings>
```

```powershell
./mvnw.cmd -B -Pgithub clean deploy
```

토큰은 소스·POM·문서에 기록하지 않는다. GitHub Actions에서는 저장소 기본 `GITHUB_TOKEN`을 사용하므로 별도 비밀값을 커밋할 필요가 없다.

## 타 프로젝트에서 소비

GitHub Packages는 private 패키지일 수 있으므로 소비 프로젝트의 Maven `settings.xml`에도 같은 `github` 서버 자격증명을 둔다. `pom.xml`에는 패키지 저장소와 BOM/스타터를 추가한다.

```xml
<repositories>
  <repository>
    <id>github</id>
    <url>https://maven.pkg.github.com/localwave-mutuus/base-common</url>
  </repository>
</repositories>

<dependencyManagement>
  <dependencies>
    <dependency>
      <groupId>ai.mutuus.common</groupId>
      <artifactId>common-platform-bom</artifactId>
      <version>0.2.4</version>
      <type>pom</type>
      <scope>import</scope>
    </dependency>
  </dependencies>
</dependencyManagement>

<dependencies>
  <dependency>
    <groupId>ai.mutuus.common</groupId>
    <artifactId>common-platform-starter-web</artifactId>
  </dependency>
</dependencies>
```

저장소에서 소비자 검증을 재현하려면 `sample-api`의 `github-consumer` 프로필을 사용한다. 이 프로필은 reactor 의존성을 사용하지 않고 GitHub Packages 저장소에서 게시된 버전을 해석한다.

```powershell
./mvnw.cmd -B -f samples/sample-api/pom.xml -Pgithub-consumer `
  -Dmaven.repo.local="$env:TEMP\common-platform-m2-consumer" clean test
```

GitHub Actions는 이 테스트를 게시 단계 뒤에 격리된 Maven 저장소로 자동 실행한다. 따라서 테스트가 통과해야 게시 workflow가 성공으로 끝나며, 테스트가 로컬 reactor 산출물을 우연히 재사용하지 않는다.

비웹 배치 서비스는 `common-platform-starter-batch`를 사용하고, 기능을 직접 조립할 때만 `common-platform`을 직접 의존한다. GitHub Packages 저장소는 해당 패키지의 POM뿐 아니라 parent/BOM/전이 의존성도 해석할 수 있어야 한다.

## 검증

게시 전에 아래 명령으로 GitHub 프로필의 effective POM과 전체 산출물 빌드를 확인한다.

```powershell
./mvnw.cmd -B -Pgithub help:effective-pom -pl lib -am '-Doutput=target/effective-pom-github.xml'
./mvnw.cmd -B clean verify
```

실제 원격 게시 성공은 GitHub Actions 실행 결과와 저장소의 **Packages** 탭에서 확인한다. 로컬에 GitHub 인증이 없으면 빌드 검증은 가능하지만 원격 게시를 성공으로 표시해서는 안 된다.
