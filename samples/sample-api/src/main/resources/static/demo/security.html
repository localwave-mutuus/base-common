Phase 0 — 보안 감사 로깅 기반 (동작)

정상 인증 (whoami) 200

유효 토큰으로 보호 리소스 접근 → 주체·권한 반환. (위배 아님, 기준선)

인증 없음 → 401 401 security.authn.failed

토큰 없이 보호 리소스 접근 → 인증 실패. clientIp·사유가 보안 로그에 남는다.

권한 부족 → 403 403 security.authz.denied

USER 토큰으로 ROLE_ADMIN 리소스 접근 → 인가 거부. 주체(principal)·사유가 보안 로그에 남는다.

Phase 1 — 신뢰경계·토큰·정보노출 (동작)

X-User-Id 스푸핑 폐기 200 security.identity.header_ignored

미인증 요청에 X-User-Id: spoofed-admin 위장 → 신뢰하지 않아 폐기. 응답의 traceContextUserId가 비어 있어야 정상(감사 created_by 위조 방지).

X-User-Id 불일치 200 security.identity.mismatch (ERROR)

인증 주체(alice)와 다른 X-User-Id: bob 주장 → 신원 위·변조 시도로 ERROR 기록(검증 주체가 우선).

JWT audience 불일치 → 401 401 security.jwt.rejected

다른 서비스용 토큰(alice~other-service, aud 불일치) → 거부. 사유(errorCode/설명) 기록. ai 프로파일에 audiences=[sample-api] 설정 필요.

오류 응답 정보 미노출 500

런타임 예외 → 500. 응답 본문의 error.exception이 null이어야 정상(내부 클래스명 미노출, 로그에만).

Phase 2~3 — 예정 (전파·마스킹·헤더)

아웃바운드 전파 차단 예정 security.propagation.blocked

비신뢰 외부 호스트로 식별/사용자 헤더 부착 차단.

설정 점검·보안 헤더 예정 security.config.*

본문 마스킹 OFF·CSRF+세션 공존·permit-all 과대 startup 경고, 보안 응답 헤더.
