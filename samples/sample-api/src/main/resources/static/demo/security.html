비우면 인증 없음(→401). ai 프로파일 mock JwtDecoder 기준. ← 케이스 화면 📜 전체 로그
Phase 0 — 보안 감사 로깅 기반 (동작)

정상 인증 (whoami) 200

유효 토큰으로 보호 리소스 접근 → 주체·권한 반환. (위배 아님, 기준선)

인증 없음 → 401 401 security.authn.failed

토큰 없이 보호 리소스 접근 → 인증 실패. clientIp·사유가 보안 로그에 남는다.

권한 부족 → 403 403 security.authz.denied

USER 토큰으로 ROLE_ADMIN 리소스 접근 → 인가 거부. 주체(principal)·사유가 보안 로그에 남는다.

Phase 1 — 신뢰경계·토큰·정보노출 (동작)

X-User-Id 스푸핑 폐기 200 security.identity.header_ignored

미인증 요청에 X-User-Id: spoofed-admin 위장 → 신뢰하지 않아 폐기. 응답의 traceContextUserId가 비어 있어야 정상(감사 created_by 위조 방지).

X-User-Id 불일치 200 security.identity.mismatch (ERROR)

인증 주체(alice)와 다른 X-User-Id: bob 주장 → 신원 위·변조 시도로 ERROR 기록(검증 주체가 우선).

JWT audience 불일치 → 401 401 security.jwt.rejected

다른 서비스용 토큰(alice~other-service, aud 불일치) → 거부. 사유(errorCode/설명) 기록. ai 프로파일에 audiences=[sample-api] 설정 필요.

오류 응답 정보 미노출 500

런타임 예외 → 500. 응답 본문의 error.exception이 null이어야 정상(내부 클래스명 미노출, 로그에만).

Phase 2 — 권한·전파·설정 점검 (동작)

권한 없는 토큰 200 security.authz.no_authorities

roles 클레임이 빈 토큰(noroles) → 인증은 되나 부여 권한 0건(사실상 모든 보호 리소스 403). 진단용으로 주체·클레임 경로를 기록.

아웃바운드 전파 차단 security.propagation.blocked 서버측

서버가 신뢰 allowlist 밖 호스트로 호출할 때 식별 헤더(X-User-Id 등)를 부착하지 않고 차단한다 (상관용 trace/span만 전파). 브라우저에서 직접 트리거하지 않는 서버-서버 동작 — 회귀 테스트 SecurityPropagationBlockIntegrationTest로 검증. mutuus.common.propagation.allowed-hosts 로 설정.

시작 시 설정 점검 security.config.* startup

기동 시 위험 조합을 1회 경고한다 — 본문 로깅+마스킹 off(masking_disabled), 세션 저장소가 있고 CSRF 설정이 비활성인 경우에만 csrf_disabled_with_session 을 남긴다. mutuus.common.security.csrf-enabled=true 인 정상 설정은 false positive 로 경고하지 않는다. permit-all 과대(permit_all_broad)도 함께 점검한다.

Phase 3 — 보안 헤더·CSRF (동작)

보안 응답 헤더 헤더 headers.enabled

하드닝 활성(ai 프로파일 headers.enabled=true) 시 응답에 Referrer-Policy·Permissions-Policy· X-Content-Type-Options 가 실린다. CSP 는 데모 HTML 인라인 스크립트를 막지 않도록 미설정.

CSRF 조건부 csrf-enabled knob

기본은 무상태 Bearer 라 CSRF 비활성(안전). 쿠키 세션 소비 서비스는 mutuus.common.security.csrf-enabled=true 로 켜면 CSRF 토큰 없는 상태변경(POST)이 403 이 된다. 회귀 SecurityHeadersCsrfIntegrationTest. (이 데모 프로파일은 CSRF 기본 비활성)
